## 一、产品是什么？

### 1.1 一句话定位

> **Crushe AI 是一款帮助用户追到crush的 AI 恋爱军师。**

我们不是情感垃圾桶（只听你哭诉），也不是鸡汤机器（喊口号），而是一个**有血有肉的"战略顾问"**——既能陪你吐槽，也能帮你出谋划策、手把手教你怎么做。

### 1.2 产品核心价值

| 价值 | 说明 |
|:----|:----|
| **看清局势** | 帮用户穿透主观滤镜，客观诊断"你们现在到底什么情况" |
| **制定策略** | 给出"你大方向该怎么走"的路线图 |
| **手把手教学** | 具体到"这条消息怎么回"、"朋友圈发什么" |
| **实时陪跑** | 7x24 小时在线，情绪疏导 + 随时答疑 |

## 二、我们的用户是谁？

### 2.1 核心用户类型

我们聚焦的是 **"明确者 (The Determined)"**：

- **特征**：对 Crush 有明确兴趣
- **判断标准**：如果对方现在立马愿意跟他在一起，他会毫不犹豫地同意
- **核心问题**：**"如何才能跟对方在一起？"**

### 2.2 典型画像：兵哥

> **"代码我能懂，但她我不懂"**

| 属性 | 描述 |
|:----|:----|
| **职业** | 某大厂工程师 |
| **背景** | 大学参军，校园与军营生活导致女性接触极少 |
| **优势** | 高学历、高收入、长相不错（硬性条件优越） |
| **问题** | 完全不懂怎么和女生相处，容易用力过猛 |

**兵哥的困境**：
- 和组内漂亮校招生加了微信
- 一个月"早安/晚安/在干嘛"的无营养尬聊后，女生回复渐冷
- 误以为是自己对她不够好 → 当众送顶配机械键盘 → 更尴尬

**如果没有干预**，兵哥面临的结局：
- 🔴 盲目发力 → 女生压力爆棚 → BE
- 🔴 自我否定 → 觉得配不上 → 主动放弃
- 🔴 归咎对方 → "我对你这么好还不理我" → 愤而放弃

## 三、产品如何解决问题？

### 3.1 核心洞察：这是一个"销售转化问题"

我们把"如何谈一场甜甜的恋爱"本质上看作一个 **销售转化率优化问题**：

| 失败原因 | 说明 | 我们的策略 |
|:--------|:----|:----------|
| **营销没做好** | 对方没发现你的好（兵哥现状） | 教用户正确展示高价值，优化互动技巧 |
| **PMF 没做好** | 你根本不是对方的菜 | 作为"风险预警"提示用户，避免无谓投入 |

### 3.2 解决方案框架

我们采用 **"Owner-Expert"（责任人-专家）** 的多 Agent 协同架构：

```
┌─────────────────────────────────────────────────────────────────────┐
│                           用户                                       │
│                            ↕                                        │
│  ┌─────────────────────────────────────────────────────────────┐   │
│  │                   Main Agent (决策中枢)                       │   │
│  │                     统一对外人格："小话"                       │   │
│  │           负责：接待、决策、调度、直接回复                      │   │
│  └─────────────────────────────────────────────────────────────┘   │
│              ↓                    ↓                    ↓            │
│  ┌──────────────────┐  ┌──────────────────┐  ┌──────────────────┐  │
│  │  Status Agent    │  │   Plan Agent     │  │  Guide Agent     │  │
│  │  🔍 诊断专家      │  │   🧭 战略参谋     │  │  🎯 战术教练     │  │
│  │  "现在是什么情况" │  │  "大方向怎么走"  │  │  "这步怎么做"    │  │
│  └──────────────────┘  └──────────────────┘  └──────────────────┘  │
└─────────────────────────────────────────────────────────────────────┘
```

**关键原则**：
- **对外统一人格**：用户感知到的始终是"小话"一个角色，不会听到"转接给分析师"
- **静默交接**：Agent 之间的切换对用户完全透明

## 四、核心架构：多 Agent 协作

### 4.1 四个核心 Agent

#### Main Agent — 决策中枢 (The CEO)

| 属性 | 说明 |
|:----|:----|
| **定位** | 用户达成目标的**最终责任人** |
| **职责** | ① 意图识别 ② 流量分发 ③ 统一对外窗口 ④ 兜底回复 |
| **可用技能** | 提问技能、咨询技能、情绪安抚技能 |

#### Status Agent — 现状分析师 (The Diagnostician)

| 属性 | 说明 |
|:----|:----|
| **定位** | 冷峻的诊断专家，负责"看清局势" |
| **输出物** | **《情感罗盘报告》**：ACR 三维评分 + L/T 阶段定位 + 核心阻力分析 |
| **核心原则** | **Truth over Comfort** — 用事实说话，不盲目共情 |

#### Plan Agent — 战略参谋 (The Strategist)

| 属性 | 说明 |
|:----|:----|
| **定位** | 宏观布局的军师，负责"制定路线图" |
| **输出物** | **《行动规划书》**：阶段划分 + 通关里程碑 |
| **核心原则** | 只要成功率不为 0，就提供当前局势下的理论最优解 |

#### Guide Agent — 战术教练 (The Drill Instructor)

| 属性 | 说明 |
|:----|:----|
| **定位** | 手把手的执行教练，负责 SOP 落地 |
| **输出物** | **《任务卡片》**：具体步骤 + 预案推演 + 反馈触发点 |
| **核心原则** | **执行到位，不问对错** — 严格遵循 Plan 的战略方向 |

### 4.2 Agent 之间的边界

```
┌────────────────────────────────────────────────────────────────────────┐
│                          清晰的职责边界                                  │
├────────────────────────────────────────────────────────────────────────┤
│                                                                        │
│   Status Agent          Plan Agent           Guide Agent               │
│   ───────────          ──────────           ──────────                │
│   "是什么"             "做什么 & 何时"       "怎么做"                    │
│                                                                        │
│   输出：诊断报告        输出：战略规划        输出：执行 SOP              │
│   ACR 评分              阶段目标             具体文案/话术               │
│   L/T 定位              里程碑               步骤分解                   │
│   核心阻力              打法原则             预案推演                   │
│                                                                        │
│   ❌ 不做具体指导       ❌ 不写具体话术       ❌ 不质疑战略               │
│   ❌ 不做长远规划       ❌ 不重新定义局势     ❌ 不做长期承诺             │
│                                                                        │
└────────────────────────────────────────────────────────────────────────┘
```

## 五、关键概念速查

### 5.1 ACR 情感物理学

用于评估关系健康度的三个维度：

| 维度 | 全称 | 含义 | 信号示例 |
|:----|:----|:----|:--------|
| **A** | Attraction (吸引力) | 硬价值与繁衍价值 | 对方是否主动开启话题？是否好奇你？ |
| **C** | Comfort (舒适感) | 安全感与信任 | 是否分享隐私？是否接纳脆弱？ |
| **R** | Romance (张力) | 暧昧博弈与不可得性 | 是否有情绪推拉？是否有心跳感？ |

### 5.2 L/T 关系坐标系

关系的发展阶段定位：

```
🟢 L 线 (主线 - The Logic of Passing)
────────────────────────────────────────
ACR 均衡同步上涨

L1 初识期 ─→ L2 吸引期 ─→ L3 暧昧期 ─→ L4 确立期
A/C/R 皆无    A > C       A+C+R 齐备    A+C+R 高位

🔴 T 线 (陷阱线 - The Logic of Stuck)
────────────────────────────────────────
要素缺失或比例畸形

T1 备胎/供养者: C >>> A（哪怕 C 再高，A 低就是备胎）
T2 兄弟/死党:   C 覆盖了 R（太熟，完全没火花）
T3 短择/炮友:   R > C（有性张力但阻断了情感交流）
```

### 5.3 Skill 技能系统

Agent 通过"渐进式披露"动态加载能力：

| 技能 ID | 名称 | 用途 |
|:--------|:----|:----|
| `inquiry` | 提问技能 | 生成结构化的引导性问题，收集用户信息 |
| `consult_answer` | 咨询技能 | 回答用户关于恋爱心理学的知识问题 |
| `emotion_support` | 情绪安抚技能 | 提供情感支持和陪伴 |

📚 **深入阅读**：[`docs/skill_demo.md`](./skill_demo.md)

### 5.4 上下文四层架构

信息的分层管理：

| 层级 | 名称 | 内容 | 特点 |
|:----|:----|:----|:----|
| Layer 0 | 系统指令 | AI 角色设定、核心原则 | 永远不变 |
| Layer 1 | 静态情报 | 用户画像、Crush 画像、关系背景 | 慢慢积累，很少变化 |
| Layer 2 | 工作上下文 | 现状报告、行动规划、行动指南 | 随任务推进更新 |
| Layer 3 | 对话历史 | 最近对话、历史摘要 | 滚动更新 |

### 7.2 核心工作流

```mermaid
graph TD
    User([用户输入]) --> Router[Router 节点]
    
    subgraph "Core Agents"
        Main[Main Agent<br/>决策中枢]
        Status[Status Agent<br/>现状分析]
        Plan[Plan Agent<br/>行动规划]
        Guide[Guide Agent<br/>行动指南]
    end
    
    subgraph "Capabilities"
        Tools[Skill Tools<br/>(ToolNode)]
    end

    Router -->|新会话| Main
    Router -->|恢复执行| Main/Status/Plan/Guide

    Main -->|call_status| Status
    Main -->|call_plan| Plan
    Main -->|call_guide| Guide
    Main -->|ask_user| End([END])
    Main -->|tool_call| Tools

    Status -->|完成| Main
    Plan -->|完成| Main
    Guide -->|完成| Main

    Tools -->|返回结果| Main
```
