# 前端展示需求规格 (Requirements Spec)

> 版本: v1.1 | 日期: 2026-04-17 | 状态: 评审修订

---

## 一、需求背景

Crushe AI 前端聊天流存在以下核心问题：
- 部分节点信息不展示或展示不完整
- 节点展示顺序与后端实际生成顺序不一致（乱序）
- 页面刷新/重新登录后，内容丢失或顺序变化

本次需求目标是彻底解决这三类问题，实现一个**稳定、有序、可持久化**的前端展示体验。

---

## 二、展示节点定义

聊天流中需要展示的节点类型及其展示形态：

### 2.1 模型推理节点（Reasoning）

| 属性 | 说明 |
|------|------|
| 来源 | DeepSeek 等模型的 `reasoning_content`（底层推理链） |
| 展示形态 | 可折叠卡片，默认折叠，标题如「正在思考...」/「思考完成」 |
| 实时性 | 推理完成后立即展示 |
| 持久化 | 刷新后保留，默认折叠状态 |

### 2.2 子图 Agent 中间思考（Subgraph Thinking）

| 属性 | 说明 |
|------|------|
| 来源 | status/plan/guide 子图 Agent 执行过程中产出的中间 AI 消息 |
| 展示形态 | 可折叠卡片，标题标注来源（如「现状分析 Agent 思考中...」） |
| 实时性 | 子图每产出一条中间消息，立即展示 |
| 持久化 | 刷新后保留 |
| **后端依赖** | **当前后端尚未实现子图中间消息的流式发射，需后端先补充实现** |

### 2.3 工具调用节点（Tool Call）

| 属性 | 说明 |
|------|------|
| 来源 | main_agent 的 tool-loop 中每次工具调用 |
| 展示形态 | 状态卡片，分两阶段：① 调用中（loading 动画 + 工具中文名称）→ ② 调用完成（显示结果摘要） |
| 工具名称 | 所有工具展示用户友好的中文名称（映射表见附录 A） |
| 实时性 | 工具开始调用时立即展示 loading 状态，完成时立即更新为完成状态 |
| 持久化 | 刷新后保留完成状态（不还原 loading 动画） |

### 2.4 报告产出卡片（Report Card）

| 属性 | 说明 |
|------|------|
| 来源 | status（现状分析）、plan（行动策略）、guide（行动指南）报告 |
| 展示形态 | **聊天流中**：简洁提示卡片（如「现状分析已完成 → 点击查看」），点击跳转到右侧面板对应 Tab |
| 生成中状态 | 报告生成过程中，聊天流展示 loading 态卡片（如「正在生成现状分析...」），完成后切换为提示卡片 |
| 面板展示 | **右侧面板为主**：展示报告完整内容，面板已存在且基本可用 |
| 实时性 | 报告开始生成时展示 loading 卡片，完成后立即切换为完成态提示卡片，同时更新面板 |
| 持久化 | 提示卡片和面板内容均持久化，刷新后直接显示完成态 |

### 2.5 提问卡片（Inquiry Card）

| 属性 | 说明 |
|------|------|
| 来源 | Agent 通过 `ask_human` 工具发起的用户提问 |
| 展示形态 | 交互式卡片，用户可填写回答并提交 |
| 实时性 | interrupt 触发后立即展示 |
| 持久化 | 已回答的提问卡片保留（显示已提交的答案），未回答的恢复交互状态 |

### 2.6 Agent 中间文本输出（AI Intermediate）

| 属性 | 说明 |
|------|------|
| 来源 | Agent 在工具调用之间产出的中间思考文本（content） |
| 展示形态 | 普通文本气泡或可折叠块 |
| 实时性 | 产出后立即展示 |
| 持久化 | 刷新后保留 |

### 2.7 最终回复（Final Response）

| 属性 | 说明 |
|------|------|
| 来源 | main_agent 最终给用户的回复消息 |
| 展示形态 | 标准助手消息气泡 |
| 实时性 | 轮次结束时展示 |
| 持久化 | 刷新后保留 |

## 三、核心需求

### 需求 R1：节点完整展示

**所有** 2.1~2.7 定义的节点类型，在模型执行过程中都必须在聊天流中展示出来，不能遗漏。

**验收标准**：
- 每次模型执行，所有产出的 reasoning、tool_call、subgraph_thinking、report、inquiry、ai_intermediate、final_response 均在聊天流中可见
- 无节点类型被静默吞掉

### 需求 R2：实时按序展示

节点在聊天流中的展示顺序必须与后端实际生成/输出的时间顺序一致。

**后端依赖**：当前 SSE 流式事件不含序列号或时间戳，需后端为每个 SSE event 增加 `seq` 字段（可复用 `turn_seq * 1000 + part_index` 方案），前端据此排序。

**验收标准**：
- 展示顺序严格遵循后端事件流的发出顺序
- 不会出现「先展示了 thinking → tool_call → report_card → 又一个 thinking，但最终 report_card 被移到了最后」这类乱序
- 允许 1~2 秒的展示延迟，但最终呈现顺序必须与生成顺序一致
- 利用后端 `seq` 字段排序，确保网络波动情况下也不会乱序

### 需求 R3：完整持久化

页面刷新或退出登录重新登录后，聊天流展示的内容与刷新前的**最终态内容和顺序一致**。

说明：不要求还原中间态效果（如 reasoning 的流式打字、tool_call 的 loading 动画），刷新后直接展示最终态即可。

**验收标准**：
- 刷新后所有节点类型（reasoning、tool_call、report_card、inquiry、ai_intermediate、final_response）均完整保留
- 刷新后各节点的展示顺序与刷新前完全一致
- reasoning 和 tool_call 等可折叠卡片刷新后保留（默认折叠状态即可）
- 报告提示卡片刷新后仍然可点击跳转到面板
- 已回答的 inquiry 卡片显示已提交状态和答案内容

### 需求 R4：报告卡片面板跳转

报告类内容（status/plan/guide）在聊天流中只展示轻量提示卡片，完整内容在右侧面板中查看。

**验收标准**：
- 聊天流中的报告卡片为简洁提示样式（如：图标 + 「现状分析已完成」 + 点击查看按钮）
- 报告生成中时展示 loading 态（如：旋转图标 + 「正在生成现状分析...」），完成后切换为完成态
- 点击完成态卡片后跳转/切换到右侧面板对应的 Tab
- 面板中展示完整报告内容
- 面板数据同样持久化，刷新后仍可查看

### 需求 R5：工具名称中文化

所有工具调用在聊天流中展示时，使用用户可理解的中文名称（完整映射见附录 A）。

**验收标准**：
- 每个工具有对应的中文展示名称映射
- 用户不会看到 `load_skill`、`update_layer1_memory` 等英文技术名称
- 中文名称准确反映工具功能
- 未知工具名降级展示为「执行操作」，不显示英文原名

### 需求 R6：轮次折叠

用户可以一键收起某一轮对话的中间过程细节（reasoning、tool_call、subgraph_thinking、ai_intermediate、report_card），只保留最终回复。

**验收标准**：
- 每轮对话的中间过程区域旁边有「收起」按钮
- 点击后折叠该轮所有中间过程节点，只保留最终回复（Final Response）和用户消息
- 再次点击可展开恢复
- 默认状态为**展开**（不收起）
- 折叠/展开状态不持久化（刷新后恢复为默认展开即可）

### 需求 R7：输入锁定

在后端处理期间和等待用户回答提问卡片期间，禁止用户发送新消息。

**验收标准**：
- 后端流式返回进行中时，输入框置灰/禁用，不可发送新消息
- 存在未回答的提问卡片（inquiry card）时，输入框同样禁用，引导用户先回答提问
- 提问卡片回答提交后或本轮流式返回结束后，输入框恢复可用
- 禁用状态下输入框显示提示文案（如「请先回答上方问题」/「正在处理中...」）

## 四、优先级

| 优先级 | 需求 | 说明 |
|--------|------|------|
| P0 | R1 节点完整展示 | 基础功能，必须先保证所有内容都展示 |
| P0 | R2 实时按序展示 | 核心体验，顺序错误会让用户困惑（含后端 seq 字段改动） |
| P0 | R3 完整持久化 | 核心体验，刷新丢数据是严重 bug |
| P0 | R7 输入锁定 | 防止状态混乱，含提问卡片 pending 场景 |
| P1 | R4 报告面板跳转 | 体验优化，改变报告展示方式 |
| P1 | R5 工具名称中文化 | 体验优化，让非技术用户能看懂 |
| P2 | R6 轮次折叠 | 体验优化，长对话场景下减少信息密度 |

---

## 五、附加需求（低优先级）

### R8：Loading 动态文案

在 Agent 执行等待期间（30秒~2分钟），优化 loading 动画，加入动态轮播文案（类似 Claude Code 风格），如：
- 「正在分析你的情况...」
- 「正在制定策略...」
- 「快好了，再等一下...」

**优先级**：P2（不阻塞主需求）

---

## 六、不在本次范围内

- 右侧面板的 UI 改版（已有且基本可用，维持现状）
- 消息气泡的样式重设计
- 移动端适配
- 性能优化（大量消息时的虚拟滚动等）
- SSE 断线重连/自动恢复（本版不处理，断线后用户手动刷新页面即可恢复完整状态）
