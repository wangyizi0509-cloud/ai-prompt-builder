## 一、整体流程总览

用户从打开产品到付费，共经历 **3 个页面**：

```
[页面 1] 开屏页               →  点击"开始诊断"
[页面 2] 诊断对话页            →  完成诊断问答
[页面 3] 诊断报告 + 付费页     →  付费 / 离开
```

预计用户完成全流程耗时：**3-8 分钟**（取决于自由描述的长度）

---

## 二、页面 1：开屏页

### 2.1 页面目标

让用户在 3 秒内完成两件事：
1. 确认"我到了对的地方"（品牌锚定）
2. 知道下一步该干什么（开始诊断）

### 2.2 页面元素

| 元素 | 必要性 | 说明 |
|:-----|:-------|:-----|
| 产品头像 | 必须 | 品牌识别 |
| 产品名称 | 必须 | - |
| Slogan | 必须 | 一句话核心价值（文案待定） |
| "开始诊断"按钮 | 必须 | 页面最醒目的元素，一触即达 |
| 案例缩略图 / 用户好评 | 可选 | 用户可看可不看，不阻挡主动线 |

### 2.3 设计原则

- 这是一个**极简的着陆页**，不是功能介绍页
- 核心行动路径只有一条：看一眼 → 点按钮
- 案例/好评如果有，放在按钮下方或次要位置，**不能抢按钮的视觉优先级**
- 类比：医院大堂——招牌显眼、导诊台显眼、锦旗墙可以有但不挡路

### 2.4 交互待讨论

- [ ] 页面是否需要滚动？还是一屏塞下？
- [ ] 案例/好评用什么形式？（轮播卡片？静态文字？截图缩略图？）
- [ ] 是否需要"了解更多"的入口？

## 三、页面 2：诊断对话页

### 3.1 页面目标

引导用户完成信息收集，同时通过"钩子"建立专业信任、制造紧迫感。

### 3.2 整体交互流程

```
┌─────────────────────────────────────────────────────────────┐
│ Phase 1：自由描述                                             │
│                                                               │
│  ┌───────────────────────────────────────┐                   │
│  │  开场话术（系统消息）：                  │                   │
│  │  "最近是发生了什么，让你想来找军师帮忙？" │                   │
│  └───────────────────────────────────────┘                   │
│                                                               │
│  ┌───────────────────────────────────────┐                   │
│  │  用户输入区：                            │                   │
│  │  · 文字输入框（支持长文）                 │                   │
│  │  · 截图上传入口（支持多张）               │                   │
│  │  · [提交] 按钮                           │                   │
│  └───────────────────────────────────────┘                   │
│                                                               │
│  用户点击提交                                                  │
│      ↓                                                        │
│  [加载状态：AI 正在分析...]                                    │
│      ↓                                                        │
├─────────────────────────────────────────────────────────────┤
│ Phase 2：第一个钩子（AI 生成）                                 │
│                                                               │
│  ┌───────────────────────────────────────┐                   │
│  │  钩子消息（系统消息样式）：               │                   │
│  │  基于用户描述的个性化判断性反馈            │                   │
│  │  （1-3 句话，引用用户具体细节）           │                   │
│  └───────────────────────────────────────┘                   │
│                                                               │
├─────────────────────────────────────────────────────────────┤
│ Phase 3：卡片补问（1-5 题，根据已知信息动态跳过）              │
│                                                               │
│  每道题的结构：                                                │
│  ┌───────────────────────────────────────┐                   │
│  │  题目文案                                │                   │
│  │  选项卡片（单选/多选）                    │                   │
│  │  [可选：自由输入补充框]                   │                   │

│  └───────────────────────────────────────┘                   │
│      ↓ 用户选完                                               │
│  ┌───────────────────────────────────────┐                   │
│  │  钩子消息（模板，秒出）                   │                   │
│  │  可能附带产品功能示例截图                  │                   │
│  └───────────────────────────────────────┘                   │
│      ↓ 进入下一题...                                          │
│                                                               │
├─────────────────────────────────────────────────────────────┤
│ Phase 4：总结性钩子 → 过渡到报告页                             │
│                                                               │
│  ┌───────────────────────────────────────┐                   │
│  │  "好，你的情况我基本了解了..."            │                   │
│  │  "接下来帮你做一个完整的诊断"             │                   │
│  └───────────────────────────────────────┘                   │
│      ↓                                                        │
│  [加载/过渡动画：生成诊断报告中...]                             │
│      ↓                                                        │
│  跳转到页面 3                                                  │

```

#### 题目 A1 | 关系性质（单选）

**题目文案**：你们是怎么认识的？

**选项**：

| 选项 | 文案 |
|:-----|:-----|
| A | 同事（同公司/同团队） |
| B | 同学（同校/同班/同社团） |
| C | 网友（社交软件/游戏/兴趣社群） |
| D | 朋友介绍/相亲 |
| E | 线下偶遇（健身房/咖啡店/活动等） |
| F | 其他（点击后展开自由输入框） |

**选完后的钩子**：

| 用户选了 | 钩子文案 |
|:---------|:---------|
| 同事 | 同事关系有个天然优势：日常接触机会多。但也有个隐藏风险——如果策略不对，尴尬会被放大十倍，因为你们天天见面。 |
| 同学 | 同学之间最容易掉进"好哥们/好闺蜜"的陷阱。舒适感有了，但张力起不来——这是我见过最多的卡点。 |
| 网友 | 线上认识的情况，最关键的变量是：你们有没有建立线下的锚点。纯线上聊天很容易变成"赛博笔友"。 |
| 朋友介绍/相亲 | 经人介绍的关系有个特殊性——双方一开始就知道这是"相亲性质"，所以对方对你的每一步动作都会过度解读。这是把双刃剑。 |
| 线下偶遇 | 线下偶遇的最大问题是联系窗口不稳定。如果没有建立固定的互动渠道，机会窗口会很快关闭。 |
| 其他 | （不触发钩子，直接下一题） |

#### 题目 A2 | 关系时长（单选）

**题目文案**：你们认识多久了？

**选项**：

| 选项 | 文案 |
|:-----|:-----|
| A | 不到 1 个月 |
| B | 1-3 个月 |
| C | 3-6 个月 |
| D | 半年到 1 年 |
| E | 1 年以上 |

**选完后的钩子**：

| 用户选了 | 钩子文案 |
|:---------|:---------|
| 不到 1 个月 | 还在早期，好消息是对方对你的印象还没固化，策略空间很大。关键是别在这个阶段犯一些不可逆的错误。 |
| 1-3 个月 | 这个阶段很关键——对方已经对你形成初步印象了。如果现在还没有明确的升温信号，说明有些东西需要调整。 |
| 3-6 个月 | 认识快半年了，如果关系还没有实质性进展，大概率是某个环节卡住了。好在现在调整还不算晚。 |
| 半年到 1 年 | 半年以上还停在这个阶段，有一个你可能不想听的事实：你很可能已经被归类了。但归类不是终局，是可以打破的。 |
| 1 年以上 | 认识超过一年了……说实话，时间越长，对方的心理定位越固化。不过我见过很多逆转案例，关键是策略要对。 |

#### 总结性钩子（所有题完成后）

**文案模板**：
> "好，你的情况我基本了解了。老实说，你的情况我之前见过很多类似的——{根据用户选择组合生成的一句定性判断}。接下来我帮你做一个完整的诊断，把问题的根源和你现在的位置说清楚。"

然后进入加载/过渡状态 → 跳转到页面 3。

---

### 3.4 "带槽位"个性化规则

当用户在自由描述中已经提及某些信息时，题目会被跳过或改写：

| 识别到用户说了... | 处理方式 |
|:-----------------|:---------|
| 关系性质（如"我同事"） | A1 跳过 |
| 时长（如"认识半年了"） | A2 跳过 |
| "表白过" | A3 选项 A 预选，题目改为"TA 当时怎么回应的？之后你们相处有变化吗？"（变成简答题） |
| "已读不回" | A4 选项 A 预选，题目改为"在这之前 TA 是怎么回你消息的？"（变成简答题） |
| "不知道该不该继续" | A5 选项 E 预选，直接跳过 |

### 3.5 设计原则

- 整个页面的**体感是对话**，不是表单——系统消息+用户回复交替出现
- 钩子是**系统发出的消息**，视觉上跟题目有区分（钩子是"反馈"，题目是"提问"）
- 题目的选项用**卡片/胶囊**样式，手指好点击，不用精确瞄准小圆点
- 钩子里**加粗的产品功能名**需要视觉突出（颜色/粗体/下划线皆可）
- 附带配图展示为**小卡片**形式，点击可放大查看

### 4.3 各区块设计要点

#### 区块 1：诊断报告

**① 状态标签**

| 用户状态 | 标签 | 视觉调性 |
|:---------|:-----|:---------|
| 对方在逐渐冷淡 | 高危滑坡期 | 红色/警告色 |
| 被当成好哥们/工具人 | 舒适区陷阱 | 橙色/警示色 |
| 对方有好感但不会推进 | 临门犹豫期 | 黄色/机会色 |
| 暴露意图后对方回避 | 信号过载期 | 橙色/警示色 |
| 刚认识，什么都没发生 | 空白探索期 | 蓝色/中性色 |
| 拒绝过但还有互动 | 僵局观察期 | 紫色/观察色 |

**② 雷达图**
- 三个顶点：吸引力(A) / 舒适感(C) / 张力(R)
- 分数范围 0-100
- 需要清晰看到哪个维度凹进去了（**不对称就是冲击力**）
- 每个维度下方一行文字解释，例："张力 18 —— 你们之间几乎没有暧昧的火花"

**③ 核心问题**
- 2-3 条，每条独立卡片样式
- 结构：**加粗的结论** + 常规字重的证据/解释
- 示例见策略文档

**④ 趋势预判**
- 一句话，视觉上可做成醒目的横幅/标注
- 基调分两种：紧迫型（"不调整会恶化"）或 希望型（"策略正确可扭转"）

#### 区块 2：锁住的内容预览

- 3 大块，每块 3 个子项
- 锁住的内容用**模糊遮罩 / 马赛克 / ████ 占位**表示
- 可以露出 1-2 个字增加好奇心
- 每块前面有 🔒 图标

#### 区块 3：信任背书

- 一行数据条：简洁、不要太大
- 短评 1-2 条：口语化，不像广告

#### 区块 4：付费 CTA

- 紧迫感文案：1 句话，基于诊断结论
- 价格卡片：突出专享价，原价划线
- "包含"列表：4 项以内
- CTA 按钮文案：**"立即解锁"**（不是"立即购买"）
- 按钮视觉：页面最突出的交互元素

### 4.4 设计原则

- 报告部分要有**仪式感**（不是随便一段文字，而是一份"正式的诊断"）
- 锁住的内容要让人有**手痒想点开**的感觉
- 整个页面的情绪节奏是：震撼（报告）→ 渴望（预览）→ 安心（背书）→ 行动（CTA）
- 付费按钮要在不滚动的情况下也能触达（考虑底部悬浮 CTA？）

## 六、关键设计约束

| 约束 | 原因 |
|:-----|:-----|
| 不能有独立的"产品介绍"步骤 | 打断用户情绪惯性 |
| 截图上传是必需的 | 信息密度最高的输入方式，用户有这个习惯 |
| 钩子不能太长（最多 3 句话） | 保持节奏，不让用户觉得在看长文 |
| 诊断报告的免费部分要足够具体 | 要让用户震撼才能建立信任 |
| 付费区的紧迫感来自诊断内容 | 不用假倒计时、不做虚假的限时活动 |
| CTA 文案用"解锁"不用"购买" | 心理暗示：东西已经准备好了，不是在花钱 |
