# 登录/注册页面重构测试用例 - 2026-01-18

## 概述
验证重构后的登录/注册页面（`auth.html`）在视觉、交互和功能上是否符合预期。

## 测试环境
- 浏览器：Chrome/Safari/Firefox (最新版)
- 环境：本地开发环境

## 测试用例

### Case 1: 页面初始化加载
- **前置条件**：访问 `/auth.html`
- **步骤**：
  1. 观察页面整体布局。
  2. 检查标题是否为 "Crushe AI"。
  3. 检查副标题是否为 "你的 AI 恋爱军师"。
  4. 检查是否默认选中“登录”选项卡。
- **预期结果**：
  - 页面背景为紫色渐变。
  - 居中显示圆角白色容器。
  - 心形图标显示正常。
  - “登录”文字为紫色，且下方有紫色短横线。

### Case 2: 选项卡切换交互
- **前置条件**：页面已加载。
- **步骤**：
  1. 点击“注册”选项卡。
  2. 点击“登录”选项卡。
- **预期结果**：
  - 点击“注册”时，下划线平滑滑动到“注册”下方，“用户名”字段淡入显示。
  - 点击“登录”时，下划线平滑滑动回“登录”下方，“用户名”字段消失。

### Case 3: 登录功能验证 (正常流程)
- **前置条件**：已有测试账号。
- **步骤**：
  1. 在“登录”页面输入正确的邮箱和密码。
  2. 点击“登录”按钮。
- **预期结果**：
  - 按钮显示“处理中...”和加载动画。
  - 弹出绿色成功提示：“登录成功，正在跳转...”。
  - 1秒后自动跳转至 `index.html`。

### Case 4: 登录功能验证 (异常流程)
- **前置条件**：页面已加载。
- **步骤**：
  1. 输入错误的邮箱或密码。
  2. 点击“登录”按钮。
- **预期结果**：
  - 弹出红色错误提示，内容由后端返回（如“Invalid password”）。
  - 提示框样式符合新设计的红色警告风格。

### Case 5: 响应式验证
- **前置条件**：使用浏览器开发者工具。
- **步骤**：
  1. 切换到移动端视图 (如 iPhone 12)。
- **预期结果**：
  - 容器宽度自适应屏幕（100% 宽度，带有左右边距）。
  - 文字和按钮大小适中，易于触控。

## 回归范围
- 注册功能（需验证字段是否必填）。
- 登录后的 Token 存储（检查 `localStorage`）。
