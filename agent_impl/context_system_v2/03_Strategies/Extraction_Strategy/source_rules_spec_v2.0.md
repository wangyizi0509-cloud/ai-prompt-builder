# 来源判断规则（Source Rules Spec v2.0）

> 目的：定义 `user_provide` / `fact` / `ai_provide` 三种来源的判断边界，保证长期记忆“可追溯、可纠错、可解释”。

适用范围：
- Layer 1（3×3 情报矩阵）
- Organize Agent 从非结构化内容提取信息时的归类

---

## 1. 三种来源的定义

| 来源 | 定义（一句话） | 典型例子 | 可靠性 |
|:---|:---|:---|:---|
| **user_provide** | 信息从用户口中来（自述/描述/转述/主观判断） | “她很温柔”“我感觉她喜欢我” | 低 |
| **fact** | 有直接证据支撑或可观察、可验证的行为事实 | 聊天截图原话；“已读不回 3 天” | 高 |
| **ai_provide** | AI 基于证据做出的分析结论（推断） | “依恋类型：焦虑型”“可能在降温” | 中 |

关键判断问题：

> **这条信息的原始出处是谁？**

---

## 2. 边界情况处理（最常见、最容易错）

### 2.1 用户转述 Crush 的话

示例：“她跟我说她最近很忙。”
- **来源**：`user_provide`  
- **原因**：信息链路是 Crush → 用户 → AI，存在转述失真可能

如果用户提供了截图/录音等证据：
- 截图原话 → `fact`
- AI 基于截图做出的推断 → `ai_provide`

---

### 2.2 用户的主观推测/感受

示例：“我感觉她在躲我。”
- **来源**：`user_provide`
- **原因**：这是用户的感受，不是证据

---

### 2.3 用户描述“可观察行为”

示例：“她已读不回 3 天了。”
- **来源**：通常归入 `fact`
- **原因**：行为本身可观察、可验证（即便没有截图，也比纯主观推测更可靠）

---

### 2.4 AI 引用证据做分析

示例：用户上传截图，AI 说：“她说‘最近忙’可能是委婉拒绝。”
- `fact`：截图原话（“她说‘最近忙’”）
- `ai_provide`：推断结论（“可能是委婉拒绝”）

> 关键：**证据与结论要拆分存储**，否则长期记忆会失去可追溯性。

---

## 3. 置信度建议（经验值）

置信度主要用于需要权衡的场景（例如动态情报），建议区间如下：

| 场景 | 建议置信度 |
|:---|:---|
| 聊天截图原话/直接证据 | 0.90–1.00 |
| 可观察行为（已读不回/拉黑等） | 0.80–0.90 |
| 用户转述他人话 | 0.60–0.75 |
| AI 强推断（证据充分） | 0.75–0.90 |
| AI 弱推断（证据有限） | 0.50–0.70 |
| 用户主观判断 | 0.30–0.50 |

> 规则目的不是“数学精确”，而是提供可解释的强弱信号，便于后续纠错与降级。
