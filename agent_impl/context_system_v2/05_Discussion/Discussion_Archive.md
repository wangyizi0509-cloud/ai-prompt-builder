# 设计取舍与常见误区（Discussion Archive）

> 这不是“历史变更记录”，而是把系统当前形态背后的关键取舍讲清楚，帮助新人建立正确直觉，避免用错层、写脏长期记忆或把 Token 打爆。

---

## 1. 为什么要分层？为什么不是一个大 Prompt？

因为上下文有两类天然矛盾的诉求：
- **要记住很多**：用户信息会无限增长
- **输入必须可控**：模型输入窗口有限且成本随长度上升

分层的本质是把信息按“稳定性、价值、时效性”分开管理：
- 长期稳定画像放 Layer 1
- 任务周期的工作产物放 Layer 2
- 最近对话语境放 Layer 3

这样每次模型调用都能在有限预算内看到“最有用”的部分。

---

## 2. 为什么 Layer 1 用“原子记忆”而不是字符串拼接？

Layer 1 的目标是长期可维护、可去重、可排序、可纠错。  
如果把所有信息拼成大段文字，会导致：
- 去重困难（语义重复无法稳定处理）
- 冲突难纠错（新证据来了很难定位替换）
- 排序混乱（时间与可信度无法结构化排序）

“原子记忆（AtomicMemory）”把信息拆到最小语义单元，天然支持：
- 按时间倒序输出
- 按来源优先级处理冲突
- 在提纯回路中做语义合并

---

## 3. 为什么要有 3×3 矩阵？“归属”和“来源”为什么要分开？

3×3 同时解决两件事：

1) **信息关于谁**（归属）：用户 / Crush / 双方关系  
2) **信息从哪来**（来源）：用户提供 / 客观事实 / AI 分析

把这两个维度拆开后，系统可以做更稳的决策：
- 同一“归属”下，事实优先于推测
- 同一“来源”下，按时间演进输出
- 证据与结论拆分存储，便于追溯与纠错

---

## 4. 为什么“动态情报”要单独放 Layer 2，并且必须过期？

短期态势（出差/情绪/忙不忙）对“当下决策”很关键，但会迅速过期。  
如果把它写进 Layer 1，会造成：
- 过期信息长期误导（比如“她最近很忙”被永远记住）
- 长期记忆被短期噪音占满

因此动态情报必须：
- 放在 Layer 2
- 带 `expire_at`
- 注入时过滤过期

---

## 5. 为什么行动指南要“渐进式披露”？

行动指南可能很多，且大多数本轮不需要细节。  
全量展开会造成：
- Token 爆炸（输入超限）
- 模型注意力被无关细节稀释

系统的做法是：
- 少量进行中的指南展开正文（便于执行）
- 其他指南只注入索引与摘要
- 需要细节时用工具 `context_loader` 按需加载并绑定到任务

---

## 6. 为什么消息栈里要有 Virtual Ack？

Virtual Ack 是一条固定的 AIMessage，放在档案注入之后、历史对话之前：
- 让模型先“阅读档案”，再“进入对话”
- 在语义上隔离背景资料与真实对话，降低提示注入与语境混淆风险
- 对 KV Cache 也友好（固定句子稳定）

---

## 7. 为什么 `<dossier>` 用 XML？

XML 的作用不是“格式好看”，而是结构稳定：
- **闭合标签**天然形成边界：背景资料 vs 指令
- 结构明确，可控字段，便于扩展
- 内容做 escape 后能降低“内容破坏结构”的风险

---

## 8. 为什么需要 processing_status（并发处理状态）？

压缩/归档/提纯是后台回路，可能和用户新消息并发发生。  
`processing_status` 的意义是：
- 防止重复触发同一个处理任务
- 在处理中可以使用快照降级，避免读取半成品状态
- 便于定位“为什么本轮没提纯/没更新”的原因
