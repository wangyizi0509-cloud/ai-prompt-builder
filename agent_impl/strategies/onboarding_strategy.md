# Onboarding 策略白皮书 (Onboarding Strategy)

## 1. 核心矛盾与背景 (Core Conflict)

### 1.1 冷启动悖论 (The Cold Start Paradox)
*   **用户侧**：急于求成，带着情绪和具体问题（如“她不回我”）而来，极度缺乏耐心填写复杂的背景问卷。
*   **模型侧**：缺乏上下文（Context）= 幻觉/废话。如果不了解双方关系阶段、过往互动模式，Agent 只能给出“多喝热水”式的平庸建议。

### 1.2 认知与预期的错位 (The Cognition Gap)
我们的核心挑战不在于技术，而在于用户心智的转化：
*   **用户预期**：把我们当成一个“聊天机器人”，随便问两句，不行就走。
*   **产品价值**：我们需要用户把我们当成“专业军师”，这需要用户付出**信任成本**（如上传隐私数据、遵循建议）。
**因此，Onboarding 的核心任务不是“欢迎用户”或“索取数据”，而是完成从“路人”到“客户”的身份转化 (Sales Conversion)。**
*   **数据（如截图）只是结果**：用户只有被“销售成功”（认可了军师的专业度与必要性），才会自愿上传高价值数据。

## 2. 战略定位 (Strategic Positioning)

我们将 Onboarding 流程重新定义为 **“急诊分诊台”**，而非“入职填表”。

### 2.1 角色分工：销售 vs 交付
为了保证产品体验的极致优化，我们将“获客”与“服务”在架构上解耦：

| 角色 | Onboarding Agent | Main Agent (+ Status Agent) |
| :--- | :--- | :--- |
| **定位** | **销售 (Sales) / 急诊护士** | **交付 (Delivery) / 专家医生** |
| **核心KPI** | **Conversion (转化率)** | **Retention (留存率/满意度)** |
| **任务** | 制造焦虑/希望，诱导用户投入数据 (截图) | 深度分析，解决实际问题，建立长期信任 |
| **心智模型** | 激进、敏锐、快节奏 | 稳重、靠谱、深思熟虑 |

### 2.2 为什么必须独立？
1.  **心智隔离**：避免 Main Agent 在“推销数据上传”和“提供长期建议”两种人设间精神分裂。
2.  **Context 纯净**：Main Agent 的 Context Window 极其宝贵，不应被一次性的诱导话术永久污染。
3.  **极速响应**：Onboarding 需秒回以留住用户，适合轻量级模型；Main Agent 需深度思考，适合重模型。

## 3. 核心策略：评估钩子 (The Assessment Hook)

我们放弃传统的“问卷调查”模式，采用 **“智能投顾 / 财富管理”** 的核心逻辑：
**Value Before Ask (先给甜头，再要数据)**。

### 3.1 虚荣性/焦虑性预览 (Vanity/Fear Preview)
用户不会为了“完善模型资料”而配合我们，但会为了 **“缓解当下的焦虑”** 或 **“验证某种可能性”** 而配合。
*   **策略**：在用户初步提供信息（如截图或关键描述）后，我们通过快速扫描，给出一个 **“制造认知差距 (Gap)”** 的《局势预警卡》。
*   **心理学原理**：
    *   **损失厌恶 (Loss Aversion)**：“如果不马上处理，下周被拉黑的概率是 85%。”
    *   **希望诱饵 (Hope Hook)**：“虽然现在是死局，但只要调整策略，胜率能回调至 60%。”

## 4. 策略执行规范 (Strategy Execution Specs)

### 4.1 预警卡触发机制 (Assessment Trigger)
为了避免“幻觉”和“机械化分析”，我们引入 **MAS (最小预警信息集)** 概念。
*   **MAS 定义**：
    1.  **数据量**：至少包含 3-5 轮有实质内容的对话截图，或用户提供了包含具体频率/时间点的主观描述（如“一周没理我”）。
    2.  **关系基调**：能大致判断是“陌生/熟人”以及“追求/被追求”的基本态势。
*   **执行逻辑**：
    *   **满足 MAS** -> 立即生成《局势预警卡》。
    *   **不满足 MAS** -> 继续追问 / 索要更多截图（话术：“这张图信息太少了，**还有没有更早一点的？或者她回复比较慢的那几次？** 那些才是关键线索。”）。

### 4.2 预警卡内容策略 (Content Strategy)
这张卡片是“诱饵”，内容必须 **“虽不完美，但极具冲击力”**。
*   **结构定义**：
    *   **A. 风险/机会定级 (The Verdict)**：使用红绿灯色块（🔴高危 / 🟡迷雾 / 🟢机会）。
    *   **B. 核心证据锚点 (The Evidence)**：必须引用一个**具体的表象特征**（如“连续3条单向提问”、“回复字数<5”），证明“我真的看了”。
    *   **C. 走势预演 (The Projection)**：基于当前趋势的短期预测（制造焦虑/希望）。
    *   **D. 诱导动作 (The Call to Action)**：明确指出当前局势的复杂性，以及为什么需要 **“军师团队”**（包含局势诊断、战略规划、行动指导）介入。核心是建立“我需要专业团队长期陪跑”的认知，而非仅推销单一的分析报告。

## 5. 执行流程 (Execution Flow)

整个 Onboarding 流程简化为极度高效的 **“三板斧”**：

### Step 1: The Ask & Check (引导与校验)
*   **动作**：用户进入后，Agent 不寒暄，直接亮明“军师”身份，要求上传聊天记录截图。
*   **校验 (Check)**：收到信息后，判断是否满足 **MAS (最小预警信息集)**。
    *   **若满足** -> 进入 Step 2。
    *   **若不满足** -> 追问关键信息，直到满足 MAS。

### Step 2: The Hook (生成预警卡)
*   **动作**：基于 MAS 信息，进行快速 OCR 和模式识别（非深度语义分析）。
*   **产出**：**《局势初判卡》** (符合 4.2 定义的结构)。
    *   **话术逻辑**：“从这几张图来看，局势比想象中严峻（或有机会）。虽然还没深挖，但我看到了几个危险信号...”

### Step 3: The Handoff (无缝交接)
*   **动作**：用户被 Hook 住，期待深度方案。Onboarding Agent 结束任务，将 Context 和 Data 移交给 Main Agent。
*   **路由指令**：输出 `suggested_action: call_status_for_initial_diagnosis`。

---

## 6. 输出物分层定义 (Deliverables)

| 维度 | Onboarding 产出：**《局势初判卡》** | Status Agent 产出：**《情感罗盘》** |
| :--- | :--- | :--- |
| **内容结构** | **评级(红绿灯) + 证据锚点 + 走势预演** | **维度评分 + 致命伤定位 + 修正方案** |
| **目的** | **Hook (钩子)**：吓唬用户 / 勾引用户 | **Value (交付)**：让用户信服 |
| **深度** | **宏观定性 (Macro)**：胜率、风险等级 | **微观归因 (Micro)**：具体哪句话说错了 |
| **信噪比** | 低 (基于表象特征) | 高 (基于语义分析) |
| **体验** | 秒出 (Flash) | 需等待 (Thinking) |

---

## 7. 路由与架构 (Routing Architecture)

### 6.1 路由路径
`Onboarding Agent` -> `Main Agent (CEO)` -> `Status Agent (Expert)`

### 7.2 为什么不直接路由给 Status Agent？
*   **CEO 中心化**：Main Agent 必须掌握用户全貌。若跳过 Main Agent，会导致 CEO 缺失“用户初次见面时的情绪与承诺”这一关键 Context。
*   **灵活性**：Main Agent 可根据用户实时反馈（如突然不想追了）打断流程，而 Status Agent 只能机械执行。

### 7.3 技术实现：隐式触发 (Implicit Trigger)
*   **机制**：利用 `suggested_action` 字段作为一次性强指令。
*   **逻辑**：
    1.  Onboarding 结束时，在 JSON 中输出 `"suggested_action": "call_status_for_initial_diagnosis"`。
    2.  Main Agent 读取到此字段，识别为 **“新客体检 SOP”** 的触发信号。
    3.  Main Agent 调用 Status Agent，获取《情感罗盘》并反馈给用户。
*   **优势**：无需在 Main Agent 的 System Prompt 中永久硬编码 Onboarding 规则，避免 Context 污染。
