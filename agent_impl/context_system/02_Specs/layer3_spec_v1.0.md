# Layer 3 对话历史 — 规范文档 v1.0

> **创建时间**: 2026-01-15  
> **状态**: 设计中  
> **目的**: 定义 Layer 3 的存储结构、写入逻辑、提取逻辑、输出格式

---

## 一、Layer 3 定位

**Layer 3 是 Agent 的「短期工作记忆」**，让 Agent 知道"刚才发生了什么"，保持对话连贯性。

### 1.1 包含 3 类内容

| 类型 | 英文名 | 说明 | 特点 |
|:----|:------|:----|:----|
| 历史摘要 | ConversationSummary | 压缩后的远古对话 | 保留语义，省 token |
| 任务笔记 | ReasoningNotes | 当前任务的推理结论 | 硬性截断，结论导向 |
| 最近对话 | RecentTurns | 滑动窗口内的对话 | 25 轮，全量保留 |

### 1.2 Token 预算

- **总预算**: ~15,000 tokens
- 历史摘要: ~1,500 tokens（5 条 × 300 tokens）
- 任务笔记: ~500 tokens（8 条 × 60 tokens）
- 最近对话: ~13,000 tokens（25 轮）

### 1.3 关键设计决策

| 决策 | 内容 |
|:----|:----|
| **砍掉 thought** | 每轮的 thought 不进对话历史，只保留 reasoning notes |
| **时间戳必须** | 每条消息都带时间戳，用于解析相对时间 |
| **Markdown 格式** | 输出用 Markdown，比 XML 更省 token |

## 二、历史摘要 (ConversationSummary)

### 2.1 定位

当对话轮次超过 25 轮触发压缩时，旧对话被压缩成摘要，存入此处。

### 2.2 存储结构

```python
ConversationSummary = TypedDict("ConversationSummary", {
    "id": str,                    # 唯一标识 (uuid[:8])
    "summary": str,               # 摘要内容
    "topics": str,                # 关键话题（逗号分隔，自由文本）
    "created_at": str,            # ISO 格式时间: "2026-01-13T14"
    "turn_range": str,            # 覆盖的轮次范围: "1-25"
})
```

### 2.3 存储示例

```json
{
  "conversation_summaries": [
    {
      "id": "a1b2c3d4",
      "summary": "用户和crush约饭被拒绝，crush说最近忙。军师分析可能是回避型，建议降低压力。",
      "topics": "约会,冷淡,回避型",
      "created_at": "2026-01-13T16",
      "turn_range": "1-25"
    }
  ]
}
```

### 2.4 写入逻辑

| 维度 | 规则 |
|:----|:----|
| **触发条件** | 对话轮次超过 25 轮 |
| **压缩方式** | LLM 生成摘要，提取关键 topics |
| **数量上限** | 最多保留 5 条摘要 |
| **任务切片** | 不做，全局存储 |
| **topics 规范** | 自由文本，不做受控词表 |

### 2.5 提取逻辑

- 全量提取最近 5 条摘要
- 按 created_at 倒序排列

### 2.6 输出格式

```markdown
## 历史摘要
- [01-13/约会,冷淡,回避型] 用户和crush约饭被拒绝，crush说最近忙。军师分析可能是回避型，建议降低压力。
- [01-10/初识,基础信息] 用户介绍了crush的基本情况：同事，认识3个月，偶尔聊天。
```

## 三、任务笔记 (ReasoningNotes)

### 3.1 定位

存储当前任务的推理结论，让 Agent 在跨轮对话中保持思维连贯。

**重要决策**：砍掉每轮的 `thought`，只保留 `reasoning notes`。

| | thought（已砍掉） | reasoning notes（保留） |
|:-|:-----------------|:-----------------------|
| **粒度** | 每轮都有 | 按需写入（关键结论才写） |
| **内容** | "这一轮我在想什么"（过程） | "我推断出了什么"（结论） |
| **token** | 随轮次线性增长 ⚠️ | 可控（主动写入 + 截断） |

### 3.2 存储结构

```python
ReasoningNote = TypedDict("ReasoningNote", {
    "id": str,                    # 唯一标识 (uuid[:8])
    "content": str,               # 笔记内容（结论导向）
    "created_at": str,            # ISO 格式时间: "2026-01-15T14:30"
    "task_id": str,               # 所属任务 ID
})

TaskState = TypedDict("TaskState", {
    "task_id": str,               # 任务 ID
    "task_name": str,             # 任务名称（语义化）
    "reasoning_notes": list[ReasoningNote],  # 推理笔记列表
    "status": str,                # 任务状态
    "created_at": str,
})
```

### 3.3 写入逻辑

#### 3.3.1 写入触发规则

| 场景 | 是否写入 | 理由 |
|:----|:-------:|:----|
| **做出重要推断** | ✅ | 核心价值 |
| **做出策略决策** | ✅ | 避免下轮做相反决策 |
| **任务阶段进展** | ✅ | 保持任务连贯性 |
| **排除某个假设** | ✅ | 避免重复推理 |
| **发现关键事实** | ❌ | 应写入 Layer 1/2 |
| **用户回答提问** | ❌ | 对话历史已有 |

#### 3.3.2 压缩策略

**硬性截断**：保留最新 8 条，超出则删除最旧的。

理由：
- 每轮笔记主要辅助后续几轮决策
- 太多轮后价值递减
- 简单可控

### 3.4 提取逻辑

- 只提取当前活跃任务的 reasoning notes
- 最多 8 条，按 created_at 正序排列

### 3.5 输出格式

```markdown
## 任务笔记「判断crush态度」
- [01-14 14:00] 决定采用降低压力策略
- [01-14 16:00] 排除了第三者可能性
- [01-15 10:00] 用户反馈crush回复变快了
- [01-15 14:00] 进入"试探升温"阶段
```

## 四、最近对话 (RecentTurns)

### 4.1 定位

滑动窗口内的原始对话，是 Agent 最直接的上下文。

### 4.2 存储结构

```python
Message = TypedDict("Message", {
    "id": str,                    # 唯一标识
    "role": Literal["user", "assistant", "system"],
    "content": str,               # 消息内容
    "created_at": str,            # ISO 格式时间: "2026-01-15T14:30"
    "task_id": Optional[str],     # 所属任务（可选）
    "metadata": Optional[dict],   # 元数据（图片解析等）
})
```

### 4.3 压缩触发条件

| 维度 | 规则 |
|:----|:----|
| **触发方式** | 按轮次 |
| **阈值** | 超过 25 轮 |
| **压缩动作** | 旧对话 → LLM 摘要 → 存入 ConversationSummary |

### 4.4 用户消息处理

#### 4.4.1 普通文本

原样保留。

#### 4.4.2 聊天记录（超长文本）

| 维度 | 规则 |
|:----|:----|
| **写入时** | 全量保留（聊天记录是核心证据） |
| **压缩时** | 提取关键信息到 Layer 1/2，历史替换为摘要 |

#### 4.4.3 图片上传

| 维度 | 规则 |
|:----|:----|
| **写入时** | 全量保留解析结果 + 标注来源 |
| **格式** | `【图片解析】\n（以下内容来自用户上传的图片）\n{解析结果}` |

#### 4.4.4 回答提问

| 维度 | 规则 |
|:----|:----|
| **格式** | `Q1: xxx / Q2: xxx\n---\n补充：xxx` |
| **说明** | 按问题顺序拼接，跳过的问题不占位 |
| **输入框补充** | 拼接在 `---` 之后 |

**示例**：
```
Q1: 上周三
Q2: 还行但有点敷衍
---
补充：她那天心情不太好
```

### 4.5 AI 消息处理

#### 4.5.1 普通回复

只抽取 `response` 字段，其他结构化字段不进历史。

#### 4.5.2 提问卡片

| 维度 | 规则 |
|:----|:----|
| **保留字段** | 只保留 `questions[].question`（问题文本） |
| **不保留** | `id`, `purpose`, `type`, `options`, `intro`, `reasoning` |
| **格式** | `【提问】\n1. 问题1\n2. 问题2` |

#### 4.5.3 子 Agent 产物

| 维度 | 规则 |
|:----|:----|
| **报告/规划/指南正文** | 不进对话历史，只存 Layer 2 |
| **通知** | 子 Agent 在 response 里简单告知用户即可 |

#### 4.5.4 系统通知

| 维度 | 规则 |
|:----|:----|
| **保留** | ✅ 保留，有助于模型连贯性 |
| **格式** | `[S 时间戳] 通知内容` |

### 4.6 提取逻辑

- 取最近 25 轮
- 按时间正序排列
- 每条消息带时间戳

## 五、输出格式

### 5.1 整体格式：Markdown + 时间戳

选择 Markdown 而非 XML 的理由：
- 更省 token（比 XML 节省 ~100 tokens）
- 结构清晰，人类可读
- 模型理解无障碍

### 5.2 时间戳格式

| 场景 | 格式 | 示例 |
|:----|:----|:----|
| **同年内** | `MM-DD HH:mm` | `01-15 14:30` |
| **跨年** | `YYYY-MM-DD HH:mm` | `2025-12-30 14:30` |

### 5.3 角色标记

| 标记 | 含义 |
|:----|:----|
| `[U 时间戳]` | User，用户消息 |
| `[A 时间戳]` | Assistant，AI 回复 |
| `[S 时间戳]` | System，系统通知 |

### 5.4 相对时间处理

| 场景 | 处理方式 |
|:----|:--------|
| **对话历史** | 存原文 + 时间戳（模型自己计算） |
| **动态情报** | 转换为绝对日期存储 |

### 5.5 完整输出示例

```markdown
## 历史摘要
- [01-13/约会,冷淡] 用户和crush约饭被拒绝，crush说最近忙。军师分析可能是回避型，建议降低压力。

## 任务笔记「判断crush态度」
- [01-14 14:00] 决定采用降低压力策略
- [01-14 16:00] 排除了第三者可能性
- [01-15 10:00] 用户反馈crush回复变快了

## 对话
[U 01-15 14:30] 她今天没回我消息
[A 01-15 14:31] 我理解你的焦虑，不过一天没回消息不一定代表什么...

[U 01-15 15:00] 【图片解析】
（以下内容来自用户上传的图片）
这是crush的朋友圈截图，发布时间01-15 12:00，配文"好累"，图片是加班的办公桌。
[A 01-15 15:02] 【提问】
1. 你们最近一次见面是什么时候？
2. 见面时她态度怎么样？
3. 最近聊天频率有变化吗？

[U 01-15 15:10] Q1: 上周三
Q2: 还行但有点敷衍
Q3: 变少了
---
补充：她那天心情不太好，她说后天要出差
[A 01-15 15:11] 收到，也就是 01-17 她会出差。根据你的描述，我更新了现状报告。

[S 01-15 15:12] 现状报告已更新
```

## 六、与其他 Layer 的关系

### 6.1 Layer 3 → Layer 1/2 的分流

| 场景 | 目标 |
|:----|:----|
| **长期事实**（如"Crush 是独生女"） | → Layer 1 |
| **短期事实**（如"下周要出差"） | → Layer 2 动态情报板 |
| **推理结论** | → Layer 3 任务笔记 |

### 6.2 压缩时的提取

当对话历史触发压缩时：
1. 生成摘要 → 存入 ConversationSummary
2. 提取长期事实 → 写入 Layer 1
3. 提取短期事实 → 写入 Layer 2 动态情报板
4. 删除旧对话
