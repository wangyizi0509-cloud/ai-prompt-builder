# 上下文组装规范 v1.0

> **创建时间**: 2026-01-15  
> **状态**: 设计中  
> **目的**: 定义各层上下文的组装顺序、格式规范，优化 KV Cache 命中率和模型指令遵循

---

## 一、设计目标

### 1.1 KV Cache 命中率优化

**原则**：内容越稳定，越应该放前面。

```
稳定性排序（高 → 低）：
Layer 0（系统指令）> Layer 1（静态情报）> Layer 2（工作上下文）> Layer 3（对话历史）> 用户消息
```

**理由**：
- LLM 推理时会缓存已处理的 KV（Key-Value）
- 如果前面的内容不变，缓存可以复用
- 放在后面的内容变化不影响前面的缓存

### 1.2 模型指令遵循优化

**两个效应**：
- **Primacy Effect（首因效应）**：开头的内容更容易被记住和遵循
- **Recency Effect（近因效应）**：结尾的内容在输出时影响更大

**策略**：
- 核心角色、禁止项 → 放开头（Layer 0）
- 输出格式、当前任务 → 放在 Layer 3 之前
- 用户最新消息 → 放最后

## 二、Token 预算分配

> 总预算基准：~70,000 tokens（适用于 Claude 3.5 / GPT-4o 等主流模型）

| Layer | 预算 | 说明 |
|:------|:-----|:----|
| **Layer 0** | ~4,000 tokens | 系统指令区 |
| **Layer 1** | ~15,000 tokens | 静态情报区 |
| **Layer 2** | ~20,000 tokens | 工作上下文 |
| **Layer 3** | ~15,000 tokens | 对话历史 |
| **输出预留** | ~8,000 tokens | 模型输出空间 |
| **弹性空间** | ~8,000 tokens | 工具结果、OCR 内容、临时推理 |
| **总计** | ~70,000 tokens | 总预算基准 |

## 三、组装顺序规范

### 3.1 完整结构图

```
┌─────────────────────────────────────────────────────────────┐
│                  🟢 KV Cache 高命中区                         │
│                    （几乎不变，可长期缓存）                     │
├─────────────────────────────────────────────────────────────┤
│  [Layer 0] 系统指令区 (~4K tokens)                           │
│    ├── 角色定义                                              │
│    ├── 核心原则 & 禁止项                                     │
│    ├── 决策模型（OODA）                                      │
│    ├── 业务理论框架                                          │
│    └── 信任优先级说明                                        │
├─────────────────────────────────────────────────────────────┤
│  [Layer 1] 静态情报区 (~15K tokens)                          │
│    ├── 用户信息（用户提供/事实/AI分析）                        │
│    ├── Crush 信息（用户提供/事实/AI分析）                      │
│    └── 双方关系（用户提供/事实/AI分析）                        │
└─────────────────────────────────────────────────────────────┘
                              ↓
┌─────────────────────────────────────────────────────────────┐
│                  🟡 KV Cache 中等命中区                       │
│                    （报告/规划更新时变化）                      │
├─────────────────────────────────────────────────────────────┤
│  [Layer 2.a] 工作上下文 - 稳定部分                            │
│    ├── 现状报告（当前版本完整内容）                            │
│    └── 行动规划（当前版本完整内容）                            │
├─────────────────────────────────────────────────────────────┤
│  [输出格式规范] (~500 tokens)                                 │
│    └── JSON 格式要求、字段说明                                │
└─────────────────────────────────────────────────────────────┘
                              ↓
┌─────────────────────────────────────────────────────────────┐
│                  🟠 KV Cache 较低命中区                       │
│                    （指南/情报/任务变化时更新）                  │
├─────────────────────────────────────────────────────────────┤
│  [Layer 2.b] 工作上下文 - 动态部分                            │
│    ├── 动态情报板（时效性信息）                               │
│    ├── 行动指南列表（元数据表格）                             │
│    └── 历史摘要（报告/规划/指南）                             │
├─────────────────────────────────────────────────────────────┤
│  [任务系统]                                                   │
│    ├── 任务列表（最近 5 个非 completed + 3 个 completed）      │
│    ├── 当前任务信息                                           │
│    └── 任务绑定的上下文（BoundContexts）                       │
└─────────────────────────────────────────────────────────────┘
                              ↓
┌─────────────────────────────────────────────────────────────┐
│                  🔴 KV Cache 低命中区                         │
│                    （每轮对话都变化）                          │
├─────────────────────────────────────────────────────────────┤
│  [Layer 3] 对话历史 (~15K tokens)                            │
│    ├── 历史摘要（最多 5 条）                                  │
│    ├── 任务笔记（最多 8 条）                                  │
│    └── 最近对话（25 轮）                                      │
├─────────────────────────────────────────────────────────────┤
│  [当前轮次]                                                   │
│    ├── 用户最新消息                                           │
│    └── （子 Agent 专用）Main Agent Brief / instruction        │
└─────────────────────────────────────────────────────────────┘
```

### 3.2 各区域变化频率

| 区域 | 变化频率 | KV Cache 效果 |
|:----|:--------|:-------------|
| Layer 0 | 几乎不变（产品迭代时改） | ✅ 高命中 |
| Layer 1 | 偶尔变化（新增记忆时） | ✅ 较高命中 |
| Layer 2.a | 中等（报告/规划更新时） | 🟡 中等命中 |
| 输出格式 | 不变 | ✅ 高命中 |
| Layer 2.b | 较频繁（指南/情报变化） | 🟠 较低命中 |
| 任务系统 | 任务切换时变化 | 🟠 较低命中 |
| Layer 3 | 每轮都变 | ❌ 无缓存 |
| 当前轮次 | 每轮都变 | ❌ 无缓存 |

## 四、各层输出格式

### 4.1 Layer 0 - 系统指令区

**位置**：Prompt 模板的开头部分

**内容**：
```markdown
# 主 Agent Prompt

你是**小话**，用户的**专属恋爱军师**。
...

## 1. 角色定义
...

## 2. 核心原则
1. **第一人称沉浸**：严禁说"我们分析师说..."
2. **成果内化**：把报告当作自己的思考结论
...

## 3. 决策模型（OODA）
...

## 4. 业务理论框架
...

## 信任优先级
> 事实 > AI分析 > 用户提供
```

### 4.2 Layer 1 - 静态情报区

**格式**：紧凑列表，每条原子记忆独立一行

```markdown
## 情报概览
> 信息可靠性：事实 > AI分析 > 用户提供。当信息冲突时，以高可靠性信息为准。

### 用户
- [01-12 09:00/AI] 依恋类型：焦虑型
- [01-10 14:00/事实] 朋友圈发了健身照
- [01-10 10:00/用户] 姓名：小明
- [01-10 10:00/用户] 年龄：26

### Crush（小红）
- [01-12 15:00/事实] 说周末要加班
- [01-12 09:00/AI] 沟通风格：直接型
- [01-10 10:00/用户] 年龄：25

### 双方关系
- [01-12 20:00/事实] 上周一起吃了晚饭
- [01-10 10:00/用户] 认识方式：朋友介绍
```

### 4.3 Layer 2.a - 现状报告 & 行动规划

**格式**：Markdown，正文用 `"""` 包围

```markdown
## 现状分析

### 当前报告
> 更新时间: 01-14 10:00 | 版本: 3

"""
{report_content}
"""

---

## 行动规划

### 当前规划
> 更新时间: 01-14 10:00 | 版本: 2

"""
{plan_content}
"""
```

### 4.4 输出格式规范

**位置**：Layer 2.a 之后，Layer 2.b 之前

```markdown
## 输出格式 (JSON)

请严格以 JSON 格式输出：

```json
{
  "task_id": "当前任务ID",
  "decision_rationale": "OODA 决策逻辑",
  "thought": "任务连贯性笔记",
  "response": "给用户的回复",
  ...
}
```

### 字段说明
- **task_id**: ...
- **response**: ...
```

### 4.5 Layer 2.b - 动态情报 & 行动指南

**格式**：动态情报用分组列表，指南用表格

```markdown
## 动态情报板
> 以下是近期的时效性信息，请务必参考。

### 用户
- [01-14 10:00] 下周三要去上海见 Crush (置信度: 0.95 - 用户明确表述)

### Crush
- [01-13 15:00] 最近工作压力大 (置信度: 0.70 - 用户转述)

---

## 行动指南

### 🔥 进行中 (2)

#### 【abc123】破冰话题准备
"""
{guide_content}
"""

### 📋 其他指南

| ID | 标题 | 状态 | 摘要 |
|-----|------|------|------|
| def456 | 约饭计划 | pending | 计划周末邀请... |
| ghi789 | 深度话题 | paused | 准备了3个话题... |

---

## 历史摘要

#### 近期报告
- **[01-12]** 关系处于好感期初期...
- **[01-08]** 刚完成破冰阶段...
```

### 4.6 任务系统

**格式**：任务列表用表格，绑定上下文分组展示

```markdown
## 任务列表

### 当前任务
- **判断Crush是否喜欢用户** [active]
  摘要：分析Crush最近的行为，判断对用户的态度

### 其他任务
| task_id | title | status | summary |
|---------|-------|--------|---------|
| a1b2c3 | 周末约会准备 | pending | 准备周末约她... |
| d4e5f6 | 破冰聊天 | completed | 成功建立初步联系 |

---

## 任务绑定上下文

### 行动指南 (2)
- [01-15 14:00] 约会邀请话术指南
- [01-14 10:00] 破冰聊天指南

### Crush 聊天记录 (1)
- [01-15 13:00] 1月10日-1月14日的聊天片段
```

### 4.7 Layer 3 - 对话历史

**格式**：Markdown + 时间戳

```markdown
## 历史摘要
- [01-13/约会,冷淡] 用户和crush约饭被拒绝，crush说最近忙...

## 任务笔记「判断crush态度」
- [01-14 14:00] 决定采用降低压力策略
- [01-14 16:00] 排除了第三者可能性
- [01-15 10:00] 用户反馈crush回复变快了

## 对话
[U 01-15 14:30] 她今天没回我消息
[A 01-15 14:31] 我理解你的焦虑，不过一天没回消息不一定代表什么...

[U 01-15 15:00] 【图片解析】
（以下内容来自用户上传的图片）
这是crush的朋友圈截图...
[A 01-15 15:02] 【提问】
1. 你们最近一次见面是什么时候？
2. 见面时她态度怎么样？
```

## 五、边界符号规范

为了让模型清晰区分各层边界，使用以下符号：

| 符号 | 用途 | 示例 |
|:----|:----|:----|
| `##` | 一级区块标题 | `## 情报概览` |
| `###` | 二级区块标题 | `### 用户` |
| `---` | 区块分隔线 | 报告/规划/指南之间 |
| `"""` | 长文本包围 | 报告正文、指南正文 |
| `> ` | 提示说明 | `> 信息可靠性：...` |
| `[时间/来源]` | 原子记忆标记 | `[01-12 09:00/AI]` |
| `[U/A/S 时间]` | 对话角色标记 | `[U 01-15 14:30]` |

## 六、子 Agent 差异

不同 Agent 的上下文组装有细微差异：

### 6.1 Main Agent

完整使用上述结构。

### 6.2 Status Agent

| 差异点 | 说明 |
|:------|:----|
| Layer 0 | 使用 `status_agent.md` 模板 |
| 增加 `{instruction}` | Main Agent 的调度指令 |
| 增加 `{last_response}` | 对话连贯性提示 |

### 6.3 Plan Agent / Guide Agent

| 差异点 | 说明 |
|:------|:----|
| Layer 0 | 使用各自的 Prompt 模板 |
| 增加 `{instruction}` | Main Agent 的调度指令 |
| Layer 2.a | 可能只需要部分报告/规划内容 |

## 八、优化建议

### 8.1 短期优化（可立即实施）

1. **调整 Prompt 模板结构**
   - 把输出格式规范从 Prompt 末尾移到 Layer 2.a 之后
   - 确保 Layer 0 和 Layer 1 连续，中间不插入动态内容

2. **Layer 2 拆分**
   - 现状报告/行动规划（相对稳定）放前面
   - 动态情报/指南列表（相对动态）放后面

3. **任务绑定上下文单独成块**
   - 从 Layer 2 分离出来
   - 放在 Layer 3 之前

### 8.2 中期优化（需要评估）

1. **Layer 1 按需召回**
   - 当前是全量注入
   - 可考虑按当前任务/用户消息相关性召回 Top-K

2. **历史摘要按任务过滤**
   - 当前是全局混合
   - 可考虑只注入与当前任务相关的历史摘要
