# AI 军师 Agent 上下文工程策略

> **核心原则**：上下文窗口是稀缺资源，所有进入窗口的信息必须经过计算和筛选，追求**高信噪比**。

---

## 一、信息分类与存储

### 1.1 静态情报（3×3 矩阵）

这类信息帮助我们**持续积累对用户、Crush、双方关系的理解**，具有长期价值。

#### 信息结构

| 归属维度 ↓ \ 来源维度 → | 用户提供 (user_provide) | 客观事实 (fact) | AI分析 (ai_provide) |
|------------------------|------------------------|----------------|---------------------|
| **用户信息** (user_info) | 用户口述的自我描述 | 用户发的朋友圈等 | AI推断（如依恋类型） |
| **Crush信息** (crush_info) | 用户描述的Crush | 聊天记录/社媒截图 | AI推断（如性格特征） |
| **双方信息** (both_info) | 用户描述的相处情况 | 互动记录/证据 | AI推断（如关系阶段） |

#### 数据结构定义

```python
class UserContext(TypedDict):
    """3×3 静态情报矩阵"""
    
    user_info: dict  # {user_provide: str, fact: str, ai_provide: str}
    crush_info: dict  # {crush_name: str, user_provide: str, fact: str, ai_provide: str}
    both_info: dict   # {user_provide: str, fact: str, ai_provide: str}
```

#### 信任优先级（冲突时的判断依据）

1. **最高可信 - 客观事实**：聊天记录、截图内容、时间戳等直接证据。这是真理。
2. **中等可信 - AI分析**：基于证据的推断。如无新证据反驳，保持沿用。
3. **最低可信 - 用户提供**：用户可能美化自己或误读对方。需用客观事实修正。

> **关于"软事实"**：部分用户口述信息虽无直接证据，但客观性强（如"crush是同班同学"、"认识3个月"），可归入「客观事实」或标注为高可信度的用户提供信息。

---

### 1.2 动态信息

这类信息对**当前任务执行**至关重要，但长期价值不确定。

| 信息类型 | 说明 | 生命周期 |
|---------|------|---------|
| **现状分析报告** | 当前关系诊断 | 新报告生成时旧报告归档 |
| **行动规划** | 战略层计划 | 新规划生成时旧规划归档 |
| **行动指南** | 战术层任务 | 任务完成时归档 |
| **用户与AI对话** | 咨询/反馈记录 | 滚动窗口，超限压缩 |
| **用户与Crush聊天记录** | 截图提取的原文 | 分层存储，按需检索 |

## 二、上下文分层架构

```
┌─────────────────────────────────────────────────────────────────┐
│  🔒 Layer 0: 系统指令区（只读常驻）                               │
│  ├─ 角色定义（小话人设）                                          │
│  ├─ 核心法则（ACR模型、L/T坐标系）                                │
│  ├─ 工具定义、安全边界                                            │
│  └─ 信任优先级说明                                                │
│  📏 预估大小：~3-4K tokens（固定）                                │
├─────────────────────────────────────────────────────────────────┤
│  📊 Layer 1: 静态情报区（常驻，高优）                              │
│  └─ 3×3 情报矩阵（前期完整，后期可压缩）                           │
│  📏 预估大小：~5-15K tokens（随积累增长）                          │
├─────────────────────────────────────────────────────────────────┤
│  📝 Layer 2: 工作上下文（当前任务相关，高优）                       │
│  ├─ 最新版现状分析报告（完整）                                     │
│  ├─ 最新版行动规划（完整）                                        │
│  ├─ 所有未执行的行动指南（完整，不可压缩）                         │
│  └─ 当前处理的聊天截图/分析结果                                    │
│  📏 预估大小：~10-20K tokens                                      │
├─────────────────────────────────────────────────────────────────┤
│  💬 Layer 3: 滚动对话区（FIFO，中优）                              │
│  ├─ 最近 30-50 轮完整对话                                         │
│  └─ 超出阈值 → 触发整理Agent → 压缩归档                           │
│  📏 预估大小：~15-20K tokens                                      │
├─────────────────────────────────────────────────────────────────┤
│  📦 Layer 4: 外部长期记忆（按需检索，低优）                         │
│  ├─ 历史报告/指南摘要（分级：中等摘要×2 + 一句话摘要×N）            │
│  ├─ 历史对话归档（压缩摘要）                                       │
│  └─ Crush聊天记录库（分层存储 + 语义检索）                         │
│  📏 常驻摘要：~2-3K tokens                                        │
│  📏 按需调用：~10-15K tokens（抽屉式完整信息）                     │
└─────────────────────────────────────────────────────────────────┘

📊 总预算：70K tokens | 可用输入：60-65K | 压缩触发阈值：55-60K
```

## 三、各层详细策略

### 3.1 Layer 0: 系统指令区

**策略**：只读常驻，永不丢弃。

**内容**：
- 角色人设（`main_agent.md` 中的角色定义部分）
- ACR情感物理学、L/T坐标系
- 输出格式要求
- 信任优先级说明

---

### 3.2 Layer 1: 静态情报区

**策略**：常驻完整输入，是 Agent 的"长期记忆核心"。

**更新机制**：
- 用户直接回答提问 → 按问题参数归类存储
- 非直接回答场景 → 由整理 Agent 从归档内容中提取归类（行动指南完成、现状分析归档、对话压缩时）

**Prompt 模板**：
```markdown
## 用户和Crush的所有信息

### 用户信息
#### 由用户提供的信息
{user_info.user_provide}
#### 客观事实
{user_info.fact}
#### 军师分析得出的信息
{user_info.ai_provide}

### Crush信息
#### Crush名称或昵称
{crush_info.crush_name}
#### 由用户提供的信息
{crush_info.user_provide}
#### 客观事实
{crush_info.fact}
#### 军师分析得出的信息
{crush_info.ai_provide}

### 双方相处信息
#### 由用户提供的信息
{both_info.user_provide}
#### 客观事实
{both_info.fact}
#### 军师分析得出的信息
{both_info.ai_provide}
```

---

### 3.3 Layer 2: 工作上下文

**策略**：当前任务相关的完整信息，高优输入。

**包含内容**：
| 字段 | 说明 | 何时输入 |
|-----|------|---------|
| `status_report` | 现状分析报告 | 有报告时完整输入 |
| `action_plan` | 行动规划 | 有规划时完整输入 |
| `action_guides` | 行动指南（可能多个） | 所有**未执行**的指南完整输入 |
| `current_screenshot_analysis` | 当前截图分析 | 正在处理截图时输入 |

**重要规则**：
- **未执行的行动指南**：可能同时存在多个，**全部完整保留**，不可压缩
- **已执行的行动指南**：走归档流程（见 Layer 4），生成摘要后可压缩
- **现状分析/行动规划**：被新版本替换时，旧版本走归档流程

---

### 3.4 Layer 3: 滚动对话区

**策略**：FIFO 滚动窗口 + 压缩归档。

**参数设置**：
- `MAX_RECENT_TURNS`: 最近保留的完整对话轮次（建议 30-50 轮）
- `MAX_TOKENS_THRESHOLD`: 对话区 token 上限（建议 15-20K）

> 💡 按每轮平均 400-500 tokens 估算，15-20K 可容纳约 30-50 轮完整对话。

**压缩触发条件**（满足任一）：
1. 对话区 tokens > `MAX_TOKENS_THRESHOLD`
2. 用户切换聊天窗口
3. 用户 2 小时无交互
4. 语义检测到话题切换

**压缩流程**：
```
[触发压缩]
    ↓
[调用整理Agent]
    ├─ 提取高价值信息 → 写入静态情报/动态信息
    └─ 生成对话摘要 → 写入历史对话归档
    ↓
[保留最近N轮，丢弃被压缩的原文]
```

---

### 3.5 Layer 4: 外部长期记忆

**策略**：摘要常驻 + 完整信息"抽屉式"按需调用。

#### 4.1 历史报告/指南存档

**摘要分级**：
| 时间距离 | 摘要级别 | 长度 | 是否常驻 |
|---------|---------|-----|---------|
| 最近 1-2 份 | 中等摘要 | 100-200字 | ✅ 常驻 |
| 更早的 | 一句话摘要 | 20-30字 | ✅ 常驻 |

**完整信息**：存储在外部，Agent 可通过工具调用获取。

**Prompt 模板（常驻部分）**：
```markdown
## 历史档案摘要

### 历史现状分析
- [最近] {status_history[0].summary}  <!-- 中等摘要 -->
- [次近] {status_history[1].summary}  <!-- 中等摘要 -->
- [更早] {status_history[2].one_liner}, {status_history[3].one_liner}...

### 历史行动指南
- [最近] {guide_history[0].summary}
- [次近] {guide_history[1].summary}
- [更早] {guide_history[2].one_liner}...

> 💡 如需查看完整历史，可调用 `get_full_history(type, index)` 工具
```

#### 4.2 Crush 聊天记录存储

**分层策略**：

| 层级 | 存储内容 | 使用方式 |
|-----|---------|---------|
| **L1 元数据** | 聊天频率、消息数、时间跨度、最后聊天时间 | 常驻上下文 |
| **L2 结构化摘要** | AI提取的关键事件、情感转折点、重要对话主题 | 常驻上下文 |
| **L3 关键片段** | 最近 N 条 + 标记为重要的对话原文 | 按需调用 |
| **L4 全量存储** | 完整聊天记录（向量化） | 语义检索调用 |

**检索方式**：
- ✅ **主动检索**（当前实现）：Agent 判断需要时主动调用检索工具
- ⏳ **被动检索**（待办）：用户上传新截图时自动关联历史

## 四、整理 Agent

### 4.1 职责

在信息**从高优变低优**的时刻，提取高价值信息完整保留。

### 4.2 触发时机

| 场景 | 触发条件 | 说明 |
|-----|---------|------|
| **行动指南完成** | 1. 前端按钮：用户点击完成按钮并提交反馈<br>2. Agent主动发现：主Agent从对话中发现用户已完成行动 | 两种方式都会自动触发归档 |
| **现状分析替换** | Status Agent生成新报告时判断为**大改**（major_rewrite） | 只有大改才归档，微调（minor_refine）不归档<br>判断标准：关系阶段变化、核心问题重新诊断、ACR评估大幅调整 |
| **对话归档** | 对话滚动窗口压缩时（每超出5轮集中压缩一次） | 自动触发 |
| **话题切换** | 咨询场景下检测到话题变化 | 待实现 |
| **超时归档** | 用户 2 小时无交互 | 待实现 |
| **窗口切换** | 用户切换到其他聊天窗口 | 待实现 |

### 4.3 输入输出

**输入**：即将从高优变低优的信息
- 完成的行动指南 + 用户反馈
- 被替换的现状分析报告
- 需要压缩的对话片段

**输出**：
1. **高价值信息提取** → 根据内容性质写入：
   - 静态情报矩阵（3×3）
   - 或动态信息的相关字段
2. **压缩摘要** → 写入对应的历史存档

### 4.4 Prompt 设计要点

```markdown
你是信息整理专家。你的任务是从即将归档的信息中提取高价值内容。

## 输入
{content_to_archive}

## 任务
1. **识别高价值信息**：哪些信息能帮助我们更好地理解用户/Crush/双方关系？
2. **分类归档**：
   - 属于用户特征的 → user_info
   - 属于Crush特征的 → crush_info  
   - 属于双方互动的 → both_info
   - 属于任务执行经验的 → 相关动态信息
3. **生成摘要**：为原始内容生成压缩摘要

## 输出格式
{
  "extracted_info": {
    "user_info": {"field": "value"},
    "crush_info": {"field": "value"},
    "both_info": {"field": "value"},
    "other": {"field": "value"}
  },
  "summary": "压缩摘要内容",
  "one_liner": "一句话摘要"
}
```

### A. Token 预算参考

**总预算**：70K tokens（含 Prompt）
**预留输出**：5-10K（模型生成 + 工具调用结果）
**可用输入**：60-65K tokens

| 层级 | Token 分配 | 说明 |
|-----|-----------|------|
| Layer 0 系统指令 | ~3-4K | 固定，不可压缩 |
| Layer 1 静态情报 | ~5-15K | 前期不压缩，接近预算才触发 |
| Layer 2 工作上下文 | ~10-20K | 未执行指南完整保留 |
| Layer 3 滚动对话 | ~15-20K | 约 30-50 轮完整对话 |
| Layer 4 常驻摘要 | ~2-3K | 中等摘要×2 + 一句话×N |
| 动态余量 | ~10-15K | 按需检索结果/抽屉内容 |

### B. 动态压缩策略

**核心原则**：前期宽松，后期收紧。

**压缩触发阈值**：当总上下文接近 **55-60K** 时，开始触发压缩策略。

**压缩优先级**（从先到后）：
1. **Layer 3 对话区**：最先压缩，保留最近 N 轮，其余归档
2. **Layer 4 历史摘要**：将中等摘要降级为一句话摘要
3. **Layer 2 已执行指南**：强制归档
4. **Layer 1 静态情报**：最后才压缩，尽量保持完整

**前期策略**（总上下文 < 50K）：
- 3×3 静态情报：完整保留，不做任何压缩
- 对话历史：完整保留
- 历史摘要：中等长度摘要

**后期策略**（总上下文 > 55K）：
- 触发对话压缩
- 历史摘要降级
- 必要时对静态情报做轻量摘要
