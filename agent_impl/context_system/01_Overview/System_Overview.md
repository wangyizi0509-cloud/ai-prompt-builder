# 上下文系统全景图

> 本文档说明整个上下文工程的完整逻辑：信息从哪来、怎么存、怎么取、怎么用，以及各模块如何协作。

---

## 一、核心问题与解决思路

### 1.1 问题

AI 的输入窗口有限（~60K tokens），但用户的信息会持续累积：
- 用户聊了 3 个月，对话记录远超上限
- 每次都把所有信息塞给 AI，塞不下、太慢、太贵

### 1.2 解决思路

**分层存储 + 按需提取 + 智能压缩**

```
用户的所有信息（无限）
        ↓
   分层存储（后台全量保留）
        ↓
   按需提取（根据当前任务筛选最相关的）
        ↓
   组装注入（拼成 ~50K tokens 的 Prompt）
        ↓
      AI 回复
```

## 二、信息的完整生命周期

一条信息从产生到被 AI 使用，会经历以下阶段：

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                           信息生命周期                                        │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                             │
│   ① 产生          ② 写入           ③ 提纯           ④ 提取          ⑤ 注入   │
│                                                                             │
│   用户发消息  →   存入 Layer 3  →  沉淀到 L1/L2  →  按需筛选  →  组装 Prompt  │
│   上传截图        （对话历史）      （长期记忆）      （最相关的）    （给 AI）   │
│   AI 生成报告     存入 Layer 2                                              │
│                   （工作上下文）                                             │
│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘
```

### 各阶段详解

| 阶段 | 做什么 | 谁负责 | 相关文档 |
|:----|:------|:------|:--------|
| **① 产生** | 用户发消息、上传图片、AI 生成报告/指南 | 用户 / 各 Agent | - |
| **② 写入** | 同步存入对应层级（追求快，不阻塞用户） | Storage Router | `storage_strategy_v1.0.md` |
| **③ 提纯** | 异步提取高价值信息，沉淀到更稳定的层级 | Organize Agent | `refining_strategy_v1.0.md` |
| **④ 提取** | 从各层取出当前需要的信息 | Context Builder | `extraction_strategy_v1.0.md` |
| **⑤ 注入** | 按固定顺序组装成 Prompt | Context Builder | `context_assembly_spec.md` |

## 三、四层架构与信息流动

### 3.1 四层结构

```
┌────────────────────────────────────────────────────────────────────┐
│  Layer 0：系统指令（只读）                                           │
│  AI 的角色设定、核心原则、决策模型                                    │
│  ─────────────────────────────────────────────────────────────────  │
│  特点：永远不变，每次对话都注入                                       │
└────────────────────────────────────────────────────────────────────┘
                                    ↑ 读取
┌────────────────────────────────────────────────────────────────────┐
│  Layer 1：静态情报（长期记忆）                                        │
│  用户画像、Crush 画像、双方关系背景                                   │
│  ─────────────────────────────────────────────────────────────────  │
│  特点：慢慢积累，很少变化                                            │
│  写入：Onboarding 时 / 对话压缩时 / 报告归档时                        │
└────────────────────────────────────────────────────────────────────┘
                                    ↑ 信息沉淀
┌────────────────────────────────────────────────────────────────────┐
│  Layer 2：工作上下文（任务周期内）                                    │
│  现状报告、行动规划、行动指南、动态情报                                │
│  ─────────────────────────────────────────────────────────────────  │
│  特点：随任务推进更新                                                │
│  写入：AI 生成报告/规划/指南时 / 提取动态情报时                        │
└────────────────────────────────────────────────────────────────────┘
                                    ↑ 信息沉淀
┌────────────────────────────────────────────────────────────────────┐
│  Layer 3：对话历史（短期记忆）                                        │
│  最近 25 轮对话、历史摘要、任务笔记                                   │
│  ─────────────────────────────────────────────────────────────────  │
│  特点：滚动更新，超过 25 轮触发压缩                                   │
│  写入：每轮对话实时写入                                              │
└────────────────────────────────────────────────────────────────────┘
```

### 3.2 信息沉淀机制

信息会从"短期"沉淀到"长期"：

```
Layer 3 对话中提到：
  "她说下周要出差"
        ↓
  Organize Agent 判断：
  - 这是短期事实（有时效性）→ 写入 Layer 2 动态情报板
  - 如果是"她是独生女"（长期事实）→ 写入 Layer 1

Layer 2 报告被新版替换：
  旧报告 → 生成摘要 → 历史归档
  报告中的关键结论（如"依恋类型：焦虑型"）→ 写入 Layer 1
```

## 四、核心模块与职责

### 4.1 模块全景

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                              用户界面                                        │
└─────────────────────────────────────────────────────────────────────────────┘
                                    │
                                    ▼
┌─────────────────────────────────────────────────────────────────────────────┐
│                           Main Agent（主控）                                 │
│  职责：理解用户意图 → 决定调用哪个子 Agent → 生成回复                          │
└─────────────────────────────────────────────────────────────────────────────┘
          │                    │                    │
          ▼                    ▼                    ▼
    ┌──────────┐        ┌──────────┐        ┌──────────┐
    │ Status   │        │ Plan     │        │ Guide    │
    │ Agent    │        │ Agent    │        │ Agent    │
    │ 现状分析  │        │ 行动规划  │        │ 行动指南  │
    └──────────┘        └──────────┘        └──────────┘
          │                    │                    │
          └────────────────────┼────────────────────┘
                               ▼
┌─────────────────────────────────────────────────────────────────────────────┐
│                        Context Builder（上下文组装器）                        │
│  职责：从 Layer 0/1/2/3 提取信息 → 按顺序组装成 Prompt                         │
└─────────────────────────────────────────────────────────────────────────────┘
                               │
                               ▼
┌─────────────────────────────────────────────────────────────────────────────┐
│                             Storage（存储层）                                │
│  Layer 1 Memory │ Layer 2 Memory │ Layer 3 Memory │ Task Registry           │
└─────────────────────────────────────────────────────────────────────────────┘
                               ▲
                               │
┌─────────────────────────────────────────────────────────────────────────────┐
│                        Organize Agent（整理员）                              │
│  职责：异步提纯 → 从对话/报告中提取高价值信息 → 沉淀到 Layer 1/2               │
└─────────────────────────────────────────────────────────────────────────────┘
```

### 4.2 各模块详解

| 模块 | 职责 | 触发时机 | 相关文档 |
|:----|:----|:--------|:--------|
| **Context Builder** | 从各层提取信息，组装成 Prompt | 每次 AI 回复前 | `context_assembly_spec.md` |
| **Organize Agent** | 提取高价值信息，生成摘要 | 对话压缩时、报告生成时、指南完成时 | `refining_strategy_v1.0.md` |
| **Task System** | 管理任务状态，绑定额外上下文 | Agent 需要更多上下文时 | `task_system_spec.md` |
| **Storage Router** | 决定信息写入哪一层 | 信息产生时 | `storage_strategy_v1.0.md` |

## 五、一个完整场景走一遍

**场景**：用户小明发来一张 Crush 的朋友圈截图，问"她这是什么意思？"

### Step 1：信息写入

```
用户消息 + 截图 OCR 结果
        ↓
    写入 Layer 3（对话历史）
```

### Step 2：上下文组装

```
Context Builder 工作：
├── Layer 0：读取系统指令（角色设定）
├── Layer 1：读取用户画像、Crush 画像、关系背景
├── Layer 2：读取当前报告、规划、动态情报
├── Layer 3：读取最近 25 轮对话 + 历史摘要
└── 按固定顺序拼接成 Prompt
```

### Step 3：AI 回复

```
Main Agent 收到组装好的 Prompt
        ↓
    分析用户意图：想了解 Crush 的心理
        ↓
    生成回复："从这条朋友圈来看，她可能最近工作压力大..."
```

### Step 4：信息沉淀（异步）

```
Organize Agent 被触发（假设对话超过 25 轮需要压缩）
        ↓
    分析被压缩的对话：
    - 发现"Crush 最近工作压力大"是短期事实
            ↓
        写入 Layer 2 动态情报板（设置 7 天过期）
    
    - 发现"Crush 喜欢在朋友圈发工作内容"是长期特征
            ↓
        写入 Layer 1 Crush 画像
```

## 六、Onboarding 与上下文工程的关系

Onboarding 是用户首次使用时的信息收集流程，它是 **Layer 1 的初始数据源**。

### 6.1 Onboarding 的作用

```
用户首次进入
    │
    ▼
┌─────────────────────────────────────┐
│  Onboarding Agent                    │
│  极速收集：用户是谁、Crush 是谁、      │
│  当前关系状态、核心痛点               │
└─────────────────────────────────────┘
    │
    ▼ 收集完成
┌─────────────────────────────────────┐
│  触发 Organize Agent                 │
│  从 Onboarding 对话中提取信息         │
└─────────────────────────────────────┘
    │
    ├── 用户画像 → Layer 1 (user_info.user_provide)
    ├── Crush 画像 → Layer 1 (crush_info.user_provide)
    ├── 关系背景 → Layer 1 (both_info.user_provide)
    └── 短期动态 → Layer 2 (dynamic_intels)
```

### 6.2 Onboarding 完成后的触发

| 触发时机 | 执行角色 | 动作 |
|:--------|:--------|:----|
| Onboarding 完成 | Organize Agent | 读取全量 Onboarding 对话，提取信息写入 Layer 1/2 |

这是上下文系统的**冷启动**——用户画像的"第一桶金"。后续通过日常对话持续积累。

### 6.3 相关文档

- Onboarding 模块说明：`agent_impl/onboarding/README.md`
- Onboarding Prompt：`agent_impl/onboarding/prompts/onboarding_agent.md`

## 九、关键设计决策

| 决策 | 原因 |
|:----|:----|
| **分层存储** | 不同信息的更新频率不同，分开管理更高效 |
| **信任优先级（事实 > AI分析 > 用户说的）** | 用户可能美化自己或误读对方，需要用客观证据修正 |
| **Layer 3 只保留 25 轮** | 对话历史增长最快，必须控制 |
| **异步提纯** | 提取高价值信息需要 LLM 调用，不能阻塞用户体验 |
| **组装顺序：稳定在前，动态在后** | 优化 KV Cache 命中率，省钱省时间 |
