# 信息价值过滤标准 (Value Filter Specification)

> **文档状态**：Draft v1.0  
> **最后更新**：2026-01-19  
> **适用范围**：Organize Agent 信息提取模块  
> **文档目的**：定义什么信息值得记录、什么信息应该过滤掉

---

## 一、问题背景

### 1.1 当前问题

Organize Agent 目前把大量无意义的对话记录到了 Layer 1，例如：
- 用户说"哈哈哈你说的对"
- Crush 说"你怕不是看多了"
- 用户说"好的我知道了"

这些信息**对理解用户/Crush/关系毫无帮助**，只会污染长期记忆，浪费 Token。

### 1.2 核心原则

> **Layer 1 的本质是"大脑的长期记忆"，只存储能帮助 AI 更好理解和服务用户的信息。**

判断标准：**"半年后这条信息还有用吗？"**
- 如果有用 → 高价值，写入 Layer 1
- 如果只是近期有用 → 中价值，写入 Layer 2 动态情报
- 如果没用 → 低价值，不记录

---

## 二、三级价值定义

### 2.1 高价值信息（必须记录到 Layer 1）

#### 定义
**能帮助 AI 长期、稳定地理解用户/Crush/关系的信息**。这类信息具有持久性，不会因为时间推移而失效。

#### 判断特征（满足任意一条即可）

| 特征 | 说明 | 
|:----|:----|
| ✅ **身份属性** | 姓名、年龄、职业、学历、家庭背景等基本信息 |
| ✅ **稳定性格** | 性格特点、沟通风格、依恋类型、行为模式 |
| ✅ **长期偏好** | 兴趣爱好、生活习惯、价值观、择偶标准 |
| ✅ **关系背景** | 如何认识、认识多久、共同圈子、关系定性（如同事/同学）|
| ✅ **里程碑事件** | 关系中的重要转折点（第一次约会、表白、吵架和好等）|
| ✅ **重大决策** | 对关系有长期影响的决定（如用户决定不再主动追了）|
| ✅ **关键态度** | Crush 明确表达的对用户的态度（如"你很好但我们不合适"）|

#### 5 个具体示例

| 原始内容 | 价值判断 | 归属 |
|:--------|:--------|:----|
| 用户说"她是独生女，家里条件挺好的" | ✅ 高价值：身份属性，长期有效 | crush_info.user_provide |
| Crush 在聊天中说"我不太喜欢粘人的男生" | ✅ 高价值：择偶标准，策略参考 | crush_info.fact |
| AI 分析"用户呈现焦虑型依恋特征" | ✅ 高价值：性格分析，长期有效 | user_info.ai_provide |
| 用户说"我们是通过朋友聚会认识的" | ✅ 高价值：关系背景，不会过期 | both_info.user_provide |
| 用户说"上周我们第一次单独吃饭" | ✅ 高价值：里程碑事件，关系进展 | both_info.user_provide |

---

### 2.2 中价值信息（记录到 Layer 2 动态情报）

#### 定义
**短期内有参考价值，但会随时间失效的信息**。这类信息对近期的策略制定有帮助，但不值得永久保存。

#### 判断特征（满足任意一条即可）

| 特征 | 说明 |
|:----|:----|
| 📅 **日程安排** | 近期的时间安排（出差、加班、考试等）|
| 💭 **当前情绪** | 近期的情绪状态（心情不好、压力大、开心等）|
| 🔄 **临时状态** | 短期内的特殊状态（生病、忙碌、在旅行等）|
| 🎯 **近期意向** | 用户近期想做的事（想约她看电影、打算周末联系）|
| ⏰ **时效性事件** | 即将发生或刚发生的事情（明天有约、昨天吵架了）|

#### 5 个具体示例

| 原始内容 | 价值判断 | 归属 |
|:--------|:--------|:----|
| 用户说"她下周要去上海出差" | 📅 中价值：日程安排，1周后失效 | Layer 2 (schedule, crush) |
| 用户说"她最近因为工作压力大心情不太好" | 💭 中价值：当前情绪，会变化 | Layer 2 (mood, crush) |
| 用户说"我这两天感冒了在家休息" | 🔄 中价值：临时状态，几天后失效 | Layer 2 (status, user) |
| 用户说"我打算这周六约她看电影" | 🎯 中价值：近期意向，执行后失效 | Layer 2 (intent, user) |
| 用户说"昨天她突然主动找我聊天了" | ⏰ 中价值：时效性事件，参考价值递减 | Layer 2 (event, both) |

---

### 2.3 低价值信息（不记录）

#### 定义
**对理解用户/Crush/关系没有任何帮助的信息**。这类信息是对话中的"噪音"，包括废话、口头禅、情绪表达、礼貌用语等。

#### 判断特征（满足任意一条即跳过）

| 特征 | 说明 | 示例 |
|:----|:----|:----|
| 🚫 **纯情绪表达** | 只是发泄情绪，没有实质信息 | "哈哈哈"、"唉"、"烦死了" |
| 🚫 **口头禅/废话** | 日常对话的填充语 | "你怕不是看多了"、"就那样吧"、"算了不说了" |
| 🚫 **礼貌用语** | 没有信息量的客套话 | "好的"、"谢谢"、"知道了"、"行" |
| 🚫 **重复确认** | 对已有信息的简单重复 | "对对对"、"是的"、"就是这样" |
| 🚫 **模糊表达** | 没有明确信息的模糊语句 | "还行吧"、"差不多"、"那种感觉" |
| 🚫 **无关闲聊** | 与用户/Crush/关系无关的话题 | 讨论天气、新闻、娱乐八卦 |
| 🚫 **AI 的回复内容** | AI 说的话不需要记录回 Layer 1 | AI 的建议、分析、安慰等 |
| 🚫 **过于泛化的信息** | 没有具体内容的笼统描述 | "通过微信联系"、"经常聊天"、"认识挺久了" |
| 🚫 **对事件的即时情绪反应** | 针对单一事件的情绪表达，不是持续状态 | "因为已读不回感到烦躁"、"她不回我好急" |

#### 5 个具体示例

| 原始内容 | 价值判断 | 处理 |
|:--------|:--------|:----|
| 用户说"哈哈哈你说的太对了" | 🚫 低价值：纯情绪表达 | 不记录 |
| Crush 说"你怕不是看多了" | 🚫 低价值：废话/口头禅 | 不记录 |
| 用户说"好的我知道了" | 🚫 低价值：礼貌用语 | 不记录 |
| 用户说"就...那种感觉你懂吗" | 🚫 低价值：模糊表达 | 不记录 |
| 用户说"今天北京下雪了好冷啊" | 🚫 低价值：无关闲聊 | 不记录 |

## 三、过滤规则（LLM 判断指南）

以下规则可直接嵌入到 Organize Agent 的 Prompt 中。

### 3.1 必须记录的情况（白名单）

```
【必须提取到 Layer 1 的信息】

当内容包含以下任意类型时，必须提取：

1. 身份信息
   - 姓名、年龄、生日
   - 职业、公司、行业
   - 学历、学校
   - 家庭情况（独生/有兄弟姐妹、父母职业等）
   - 所在城市、籍贯

2. 性格与风格
   - 性格描述（内向/外向、敏感/大条等）
   - 沟通风格（主动/被动、直接/委婉等）
   - 行为模式（容易紧张、喜欢逃避等）
   - AI 分析的依恋类型

3. 长期偏好
   - 兴趣爱好（喜欢健身、爱看电影等）
   - 生活习惯（早睡、不喝酒等）
   - 价值观（重视家庭、事业心强等）
   - 择偶标准（不喜欢粘人、喜欢有上进心等）

4. 关系背景
   - 认识方式（朋友介绍、同事、相亲等）
   - 认识时长
   - 共同社交圈
   - 当前关系定性（暧昧、朋友、同事等）

5. 重要事件
   - 关系里程碑（第一次约会、表白、确认关系等）
   - 关键冲突（吵架、误会、冷战等）
   - 重大态度表达（Crush 说"你很好但我们不合适"）

6. AI 的分析结论
   - 依恋类型判断
   - 性格特征分析
   - 沟通风格判断
   - 核心问题识别
```

### 3.2 绝对不记录的情况（黑名单）

```
【禁止记录的信息类型】

遇到以下情况，直接跳过，不要记录：

1. 纯语气词/情绪表达
   - "哈哈哈"、"嘿嘿"、"唉"
   - "烦死了"、"好累啊"、"开心"
   - "..."、"？？？"、"！！！"

2. 口头禅/废话
   - "你怕不是xxx"、"我觉得吧"、"就那样"
   - "算了不说了"、"反正就是"、"懂我意思吧"
   - "就...那种感觉"、"就是那个意思"

3. 简单应答
   - "好的"、"行"、"OK"、"嗯嗯"
   - "知道了"、"明白"、"收到"
   - "对对对"、"是的"、"没错"
   - "谢谢"、"感谢"、"辛苦了"

4. 无实质内容的提问
   - "真的吗"、"是吗"、"然后呢"
   - "那怎么办"、"你说呢"

5. 与用户/Crush/关系无关的话题
   - 讨论天气、新闻、社会事件
   - 聊娱乐八卦、游戏、体育比赛
   - 纯粹的工作/技术讨论（除非说明了职业特征）

6. AI（小话）说的话
   - AI 的建议、分析、安慰、鼓励
   - AI 的提问、引导、确认
   - （AI 说的内容是输出，不是需要记录的情报）

7. 过于泛化/通用的信息
   - "通过微信联系"、"经常聊天"、"认识挺久了"
   - 没有具体时间、频率、内容的笼统描述
   - （太泛化 = 没有信息量）

8. 对特定事件的即时情绪反应
   - "因为已读不回感到烦躁"、"她不回我好急"
   - 这是对单一事件的瞬时反应，不是持续的情绪状态
   - （与 Layer 2 mood 的区别：mood 是"Crush最近压力大"这种持续状态）

9. 已在 Layer 2 常驻的信息
   - 关系阶段（L1-L4/T1-T3）
   - ACR 三维分析
   - 核心问题/风险点
   - （这些在现状报告中已经有了，不要重复记录）
```

### 3.3 模糊情况的处理原则

```
【模糊情况判断原则】

当无法明确判断是否记录时，问自己三个问题：

Q1: 这条信息能帮助 AI 更好地理解用户/Crush/关系吗？
    - 如果能 → 考虑记录
    - 如果不能 → 不记录

Q2: 半年后这条信息还有参考价值吗？
    - 如果有 → 记录到 Layer 1
    - 如果只有短期价值 → 记录到 Layer 2 动态情报
    - 如果没有 → 不记录

Q3: 如果不记录这条信息，AI 的服务质量会下降吗？
    - 如果会 → 记录
    - 如果不会 → 不记录

【宁缺毋滥原则】

当仍然无法判断时：
- 倾向于不记录
- 低质量的记录比不记录更糟糕，因为会污染长期记忆
- 重要信息通常会在后续对话中反复出现，不会因为漏记一次就丢失
```

## 四、场景化过滤示例

### 4.1 典型对话过滤示例

**原始对话片段：**
```
用户: 她今天又已读不回我了，唉烦死了
AI: 能理解你的感受。她最近是不是比较忙？
用户: 她说这周要加班，但我也不确定是不是真的
AI: 你们现在主要通过什么方式联系？
用户: 微信吧，她朋友圈不怎么发
AI: 明白了。她平时是什么性格？主动还是比较被动？
用户: 挺被动的，基本都是我主动找她
AI: 嗯嗯，焦虑型依恋配上回避型的人确实容易这样
用户: 哈哈哈你说的太对了，就是这种感觉
```

**过滤结果：**

| 内容 | 价值判断 | 处理 |
|:----|:--------|:----|
| "她今天又已读不回我了" | 📅 中价值：时效性事件 | Layer 2 (event) |
| "唉烦死了" | 🚫 低价值：纯情绪表达 | 不记录 |
| "因为已读不回感到烦躁" | 🚫 低价值：对事件的即时情绪反应 | 不记录 |
| "她说这周要加班" | 📅 中价值：日程安排 | Layer 2 (schedule) |
| "但我也不确定是不是真的" | 🚫 低价值：模糊表达 | 不记录 |
| "微信吧" / "通过微信联系" | 🚫 低价值：信息太泛（谁不用微信？）| 不记录 |

| "哈哈哈你说的太对了" | 🚫 低价值：纯情绪表达 | 不记录 |
| "就是这种感觉" | 🚫 低价值：废话 | 不记录 |

## 五、与现有系统的集成

### 5.1 与 organize_agent_strategy.md 的关系

本规范是 `organize_agent_strategy.md` 的**补充**，解决的是不同问题：

| 规范 | 解决的问题 | 核心问题 |
|:----|:---------|:--------|
| **organize_agent_strategy.md** | 信息分类 | "这条信息归哪里？"（3×3 矩阵 + 长短期分流）|
| **value_filter_spec.md**（本文档）| 信息价值 | "这条信息值得记吗？"（三级价值判断）|

**执行顺序：**
```
信息输入
    │
    ▼
┌─────────────────────────────────────────┐
│  Step 1: 价值过滤（本文档）               │
│  → 判断是高价值/中价值/低价值            │
│  → 低价值直接丢弃                        │
└─────────────────────────────────────────┘
    │ 高价值/中价值信息
    ▼
┌─────────────────────────────────────────┐
│  Step 2: 分类归档（organize_agent_strategy）│
│  → 高价值：判断归属 + 来源，写入 Layer 1  │
│  → 中价值：判断类型 + 归属，写入 Layer 2  │
│  ⚠️ 互斥原则：同一条信息只能进入一个层   │
└─────────────────────────────────────────┘
```

**⚠️ 分流互斥规则**：
- Layer 1 和 Layer 2 是**互斥**的，同一条信息**不能同时**写入两个地方
- 短期有效的信息（日程、情绪、状态、意向）→ 只进 Layer 2（动态情报）
- 长期有效的信息（身份、性格、偏好、背景）→ 只进 Layer 1

❌ 错误："Crush这周要加班" 同时写入 Layer 1 和动态情报
✅ 正确："Crush这周要加班" 只写入动态情报（schedule）
```
