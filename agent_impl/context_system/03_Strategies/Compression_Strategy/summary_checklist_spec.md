# 摘要质量标准规范 v1.0

> **创建时间**: 2026-01-19  
> **状态**: 待验证  
> **目的**: 定义 4 类摘要的质量标准和检查清单，确保摘要质量一致性

---

## 一、通用原则

### 1.1 摘要的核心目标

摘要是为了在**有限 Token 预算**内，让 Agent 快速理解历史上下文，做出正确决策。

**好摘要的三个标准**：

| 标准 | 说明 | 反例 |
|:----|:----|:----|
| **信息密度高** | 每句话都有决策价值 | 废话太多，重要信息淹没 |
| **可操作性强** | 读完就知道该做什么、该注意什么 | 只有描述，没有结论 |
| **上下文可追溯** | 能还原关键事实的来龙去脉 | 只有结论，丢失背景 |

### 1.2 字数控制原则

| 摘要类型 | 字数范围 | 原则 |
|:--------|:--------|:----|
| **中等摘要 (summary)** | 100-200 字 | 保留核心结论 + 关键证据 |
| **一句话摘要 (one_liner)** | 20-30 字 | 只保留「结果」或「结论」 |
| **对话摘要** | 50-100 字 | 话题 + 结论 + 待办 |

### 1.3 信息密度要求

```
❌ 低密度（废话多）：
"在这次对话中，用户和 AI 进行了深入的交流，讨论了很多话题，
包括用户的感情问题和一些相关的建议。"（47字，信息量≈0）

✅ 高密度（信息多）：
"用户分享了 Crush 已读不回的情况，AI 判定为需求感过强，
建议冷却 3 天后用轻话题重新开场。"（47字，3个关键信息点）
```

**密度检查公式**：`有效信息点数 ÷ 字数 ≥ 0.05`（每 20 字至少 1 个信息点）

## 二、对话摘要标准

### 2.1 目的

| 问题 | 答案 |
|:----|:----|
| **给谁看？** | Agent（AI），在下一次对话时作为历史背景 |
| **用来做什么？** | 快速理解「之前聊了什么」「结论是什么」「有什么待办」 |
| **被放在哪里？** | Layer 3 的 `conversation_summaries`，最多保留 5 条 |

### 2.2 必须包含的内容（检查清单）

```markdown
## 对话摘要质量检查清单

生成对话摘要时，确保包含以下内容：

- [ ] **核心话题**：这次对话主要讨论了什么？（1-2 个主题）
- [ ] **关键结论**：讨论后得出了什么结论/判断？
- [ ] **新信息**：用户透露了什么新信息？（如果有）
- [ ] **待办事项**：有什么需要跟进的？（如果有）
- [ ] **情绪状态**：用户的情绪/状态如何？（如果明显）
```

### 2.3 不应包含的内容

| ❌ 不应包含 | 原因 |
|:----------|:----|
| 对话的寒暄/客套话 | 无决策价值 |
| 用户的重复抱怨（原话） | 已提取关键点即可 |
| AI 回复的完整策略论述 | 策略在其他地方存档 |
| 模糊描述（"讨论了很多"） | 无实际信息 |
| 时间戳细节 | 元数据已有，无需重复 |

### 2.4 好/坏示例对比

**场景**：用户分享了和 Crush 聊天时被已读不回的经历，AI 分析后给出建议。

---

**❌ 坏示例**（60 字，密度低）：
```
用户今天来找 AI 聊天，分享了一些感情方面的困扰。AI 认真倾听后，
给出了一些建议。用户表示会考虑。整体对话氛围不错。
```

**问题**：
- 没有具体话题（什么困扰？）
- 没有结论（什么建议？）
- 没有新信息点
- 全是废话

---

**✅ 好示例**（68 字，密度高）：
```
【话题】Crush 已读不回问题
【情况】用户连发 3 条消息后 Crush 24 小时未回复，用户焦虑
【结论】AI 判定需求感过强，建议冷却 3 天
【待办】3 天后用轻松话题（周末计划）重新开场
```

**优点**：
- 话题明确
- 关键数据保留（3 条消息、24 小时、3 天）
- 有结论和待办

## 三、现状报告摘要标准

### 3.1 目的

| 问题 | 答案 |
|:----|:----|
| **给谁看？** | Agent（AI），在制定策略时参考历史诊断 |
| **用来做什么？** | 了解「之前的关系状态」「问题是什么」「如何演变」 |
| **被放在哪里？** | Layer 2 的 `status_report_history`，注入时最近 2 份用 summary，更早 3 份用 one_liner |

### 3.2 必须包含的内容（检查清单）

```markdown
## 现状报告摘要质量检查清单

生成报告摘要时，确保包含以下内容：

- [ ] **关系阶段**：当时处于什么阶段？（L1-L4 / T1-T3）
- [ ] **核心问题**：主要障碍/风险是什么？
- [ ] **关键发现**：这份报告最重要的洞察是什么？
- [ ] **态势判断**：Crush 对用户的态度如何？
- [ ] **建议方向**：报告建议的应对方向（1 句话）
```

### 3.3 不应包含的内容

| ❌ 不应包含 | 原因 |
|:----------|:----|
| ACR 评分细节 | 太细节，摘要只需结论 |
| 完整的 SWOT 分析 | 原报告有，摘要只取核心 |
| 重复的基本信息（如 Crush 年龄） | 已在 Layer 1 存档 |
| 历史对话内容回顾 | 对话摘要负责 |

### 3.4 好/坏示例对比

**场景**：一份分析用户与 Crush 关系的诊断报告。

---

**❌ 坏示例**（85 字，缺乏结构）：
```
这份报告分析了用户和 Crush 的关系现状。用户是一个 26 岁的程序员，
Crush 是他的同事。两人认识 2 个月了，经常聊天。AI 认为用户有一些
需要改进的地方，建议用户注意自己的表现。
```

**问题**：
- 没有阶段判断
- "有一些需要改进"太模糊
- 重复基本信息（年龄、职业）
- 没有态势判断

---

**✅ 好示例**（120 字，结构清晰）：
```
【阶段】L2 好感期初期，但有 T1 备胎风险信号
【核心问题】用户需求感过强 — 消息频率过高，追问多，给对方压力
【态势】Crush 态度从热情降温至平淡，回复变短、主动减少
【关键发现】Crush 回复中出现"再说吧""最近忙"等推脱话术
【方向】建议进入 7 天冷冻期，降低主动频率，等待 Crush 主动信号
```

**优点**：
- 阶段清晰（L2 + T1 风险）
- 问题具体（需求感过强的具体表现）
- 有证据支撑（推脱话术）
- 有明确方向

## 四、行动规划摘要标准

### 4.1 目的

| 问题 | 答案 |
|:----|:----|
| **给谁看？** | Agent（AI），在生成行动指南时参考战略框架 |
| **用来做什么？** | 了解「之前的战略目标」「分了几个阶段」「里程碑是什么」 |
| **被放在哪里？** | Layer 2 的 `action_plan_history`，注入时最近 2 份用 summary，更早 3 份用 one_liner |

### 4.2 必须包含的内容（检查清单）

```markdown
## 行动规划摘要质量检查清单

生成规划摘要时，确保包含以下内容：

- [ ] **阶段性目标**：这个规划想达成什么？
- [ ] **核心策略**：采用什么策略/打法？（1 句话）
- [ ] **阶段划分**：分几个阶段？每阶段关键词是什么？
- [ ] **里程碑**：什么信号表示可以进入下一阶段？
- [ ] **关键原则**：执行时要注意的红线/禁忌（如果有）
```

### 4.3 不应包含的内容

| ❌ 不应包含 | 原因 |
|:----------|:----|
| 详细的每日任务安排 | 太细节，属于行动指南 |
| 背景分析（为什么制定这个规划） | 现状报告摘要已覆盖 |
| 具体话术/模板 | 行动指南负责 |

### 4.4 好/坏示例对比

**场景**：一份帮助用户脱离备胎边缘、重建吸引力的规划。

---

**❌ 坏示例**（70 字，信息模糊）：
```
这份规划帮助用户改善和 Crush 的关系。规划分为几个阶段，每个阶段
有不同的任务。用户需要按照计划执行，逐步改善自己的表现，
争取获得 Crush 的好感。
```

**问题**：
- "几个阶段"是几个？
- "不同的任务"是什么？
- 没有策略、没有里程碑
- 等于没说

---

**✅ 好示例**（150 字，结构清晰）：
```
【目标】从 T1 备胎边缘恢复到 L2 好感期稳定状态
【核心策略】"撤退 → 建设 → 重启"三阶段打法
【阶段划分】
  - Phase 1（冷冻期，7天）：禁止主动联系，只回不发
  - Phase 2（建设期，14天）：通过朋友圈展示价值，侧面吸引
  - Phase 3（重启期）：用自然契机重新开启对话
【里程碑】Crush 主动发起非工作话题 = 可进入 Phase 3
【红线】禁止追问"你怎么不理我"类话题
```

**优点**：
- 目标量化（从 T1 到 L2）
- 策略命名清晰
- 阶段有时间范围和关键词
- 里程碑具体可判断
- 有红线提醒

## 五、行动指南摘要标准

### 5.1 目的

| 问题 | 答案 |
|:----|:----|
| **给谁看？** | Agent（AI），在管理任务和生成新指南时参考 |
| **用来做什么？** | 了解「做了什么任务」「结果如何」「用户反馈是什么」 |
| **被放在哪里？** | Layer 2 的 `action_guides`，根据状态展示不同详细程度 |

**特别重要**：行动指南摘要是**唯一保留用户执行反馈的地方**。用户反馈包含高价值信息（Crush 的真实反应），必须完整保留！

### 5.2 必须包含的内容（检查清单）

```markdown
## 行动指南摘要质量检查清单（已完成状态）

生成指南摘要时，确保包含以下内容：

- [ ] **任务概述**：这个任务要做什么？（1 句话）
- [ ] **执行情况**：用户做了吗？怎么做的？
- [ ] **用户反馈**：用户说了什么？（保留原话关键词）
- [ ] **Crush 反应**：Crush 有什么反应？（如果有）
- [ ] **关键收获**：从这次行动中学到/发现了什么？
- [ ] **后续影响**：这次结果对下一步有什么影响？（如果有）
```

### 5.3 不应包含的内容

| ❌ 不应包含 | 原因 |
|:----------|:----|
| 完整的执行 SOP 步骤 | 原指南有，摘要只需结果 |
| 所有预案（顺利/平淡/困难） | 只保留实际发生的 |
| AI 的详细分析论述 | 现状报告负责 |

### 5.4 好/坏示例对比

**场景**：用户执行了"发朋友圈展示生活"的任务，Crush 点赞了。

---

**❌ 坏示例**（55 字，丢失反馈）：
```
用户完成了发朋友圈的任务。这是一个展示价值的策略，目的是让
Crush 注意到用户的生活品质。任务已经完成了。
```

**问题**：
- 没有用户反馈
- 没有 Crush 反应
- 没有收获/结论
- 重复解释策略目的

---

**✅ 好示例**（120 字，反馈完整）：
```
【任务】发布展示生活品质的朋友圈（周末咖啡店 + "难得清闲"文案）
【执行】用户于周六下午发布，全员可见
【用户反馈】"发了！她点赞了，而且是发完 10 分钟内"
【Crush 反应】10 分钟内点赞，但无评论
【关键收获】Crush 关注着用户朋友圈，态度未完全冷却
【后续】可以尝试下一步：评论区互动或发起话题
```

**优点**：
- 任务具体（有内容有文案）
- 用户反馈保留原话关键词
- Crush 反应有细节（10 分钟内）
- 有收获和后续建议

## 六、检查清单速查表

以下清单可直接嵌入 Prompt 使用：

```markdown
## 摘要质量检查清单

### 通用检查（所有摘要适用）
- [ ] 信息密度：每 20 字至少 1 个有效信息点
- [ ] 无废话：没有"进行了讨论"等无意义描述
- [ ] 结论明确：读完知道"所以呢？"
- [ ] 字数合规：summary 100-200 字，one_liner 20-30 字

### 对话摘要检查
- [ ] 有核心话题（1-2 个）
- [ ] 有关键结论/判断
- [ ] 有新信息点（如果有）
- [ ] 有待办事项（如果有）

### 现状报告摘要检查
- [ ] 有关系阶段（L/T 阶段）
- [ ] 有核心问题/风险
- [ ] 有态势判断（Crush 态度）
- [ ] 有建议方向

### 行动规划摘要检查
- [ ] 有阶段性目标
- [ ] 有核心策略（1 句话）
- [ ] 有阶段划分
- [ ] 有里程碑/成功标志

### 行动指南摘要检查（已完成状态）
- [ ] 有任务概述
- [ ] 有用户反馈（保留原话关键词！）
- [ ] 有 Crush 反应（如果有）
- [ ] 有关键收获
```

## 七、摘要模板

### 7.1 对话摘要模板

```
【话题】{1-2 个核心话题}
【情况】{用户遇到的情况/问题，1 句话}
【结论】{讨论后的判断/建议，1 句话}
【待办】{需要跟进的事项，可选}
```

### 7.2 现状报告摘要模板

```
【阶段】{L?/T? 阶段判断}
【核心问题】{主要障碍/风险}
【态势】{Crush 态度描述}
【关键发现】{最重要的洞察}
【方向】{建议的应对方向}
```

### 7.3 行动规划摘要模板

```
【目标】{阶段性目标}
【核心策略】{策略/打法名称}
【阶段划分】
  - Phase 1（{时长}）：{关键词}
  - Phase 2（{时长}）：{关键词}
  - ...
【里程碑】{进入下一阶段的信号}
【红线】{禁忌/注意事项，可选}
```

### 7.4 行动指南摘要模板（已完成状态）

```
【任务】{任务名称和核心内容}
【执行】{用户实际做了什么}
```

## 八、常见问题与错误

### 8.1 常见错误

| 错误类型 | 示例 | 修正 |
|:--------|:----|:----|
| **信息丢失** | 只写"用户完成任务" | 必须写做了什么、结果如何 |
| **反馈丢失** | 不写用户反馈 | 用户原话是高价值信息，必须保留 |
| **模糊描述** | "进行了一些讨论" | 必须具体：讨论了什么、结论是什么 |
| **重复基础信息** | 每次都写"Crush 是同事" | 基础信息在 Layer 1，摘要不重复 |
| **只有过程没有结果** | 只描述发生了什么 | 必须有结论/判断/收获 |

### 8.2 自检问题

生成摘要后，问自己：

1. **「所以呢？」测试**：读完这个摘要，我知道该做什么/该注意什么吗？
2. **「重要信息」测试**：如果只能记住 3 件事，这个摘要帮我记住了吗？
3. **「丢失」测试**：如果原内容删除，只保留这个摘要，关键信息还在吗？
4. **「反馈」测试**（行动指南）：用户的原话/Crush 的反应保留了吗？
