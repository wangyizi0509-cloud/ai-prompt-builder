# 上下文压缩策略 (Compression Strategy) v1.0

> **创建时间**: 2026-01-18  
> **状态**: 生效中  
> **目的**: 系统定义上下文压缩的触发条件、摘要生成规范、信息归档规则  
> **代码对应**: `graph/archive_manager.py`, `graph/nodes/organize_agent.py`

本文档是上下文压缩系统的综合策略指南，覆盖对话压缩、报告归档、指南归档、任务推理压缩四大场景。

---

## 一、压缩系统总览

### 1.1 核心目标

上下文压缩的目标是在**不丢失关键信息**的前提下，将无限增长的用户数据控制在有限的 Token 预算内。

```
用户信息（无限增长）
        ↓
    分层存储（全量保留）
        ↓
    智能压缩（提取精华）
        ↓
    按需组装（Token 可控）
        ↓
    AI 高质量回复
```

### 1.2 四层压缩职责

| Layer | 压缩需求 | 压缩方式 | 触发时机 |
|:------|:--------|:--------|:--------|
| Layer 0 | 无 | - | - |
| Layer 1 | 增量去重 | LLM 语义判断 + 规则覆盖 | 信息写入时 |
| Layer 2 | 摘要归档 | LLM 生成 summary/one_liner | 报告/指南状态变更时 |
| Layer 3 | 轮次压缩 | LLM 生成对话摘要 + 信息分流 | 对话超过 25 轮时 |

### 1.3 压缩系统架构

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                            压缩触发器 (Triggers)                              │
├─────────────────────────────────────────────────────────────────────────────┤
│  对话压缩触发器    │  报告归档触发器    │  指南归档触发器   │  推理压缩触发器    │
│  Layer3 > 25轮    │  新报告生成时      │  指南进入终态    │  reasoning > 10   │
└─────────────────────────────────────────────────────────────────────────────┘
                                      │
                                      ▼
┌─────────────────────────────────────────────────────────────────────────────┐
│                         Organize Agent (整理员)                              │
│  职责：提取高价值信息、生成摘要、判断归档目标层级                               │
└─────────────────────────────────────────────────────────────────────────────┘
                                      │
          ┌───────────────────────────┼───────────────────────────┐
          ▼                           ▼                           ▼
┌─────────────────┐       ┌─────────────────┐       ┌─────────────────┐
│ Layer 1 写入     │       │ Layer 2 写入     │       │ Layer 3 写入     │
│ 静态情报更新      │       │ 动态情报/摘要    │       │ 对话摘要         │
└─────────────────┘       └─────────────────┘       └─────────────────┘
```

## 二、压缩触发矩阵

### 2.1 触发场景总览

| 触发场景 | 触发条件 | 输入数据 | 产出目标 |
|:--------|:--------|:--------|:--------|
| **对话压缩** | Layer 3 对话轮次 > 25 | 最早 N 轮对话 | L1 情报 + L2 动态 + L3 摘要 |
| **报告归档** | 新报告生成（替换旧版） | 旧报告正文 | L1 关键结论 + L2 历史摘要 |
| **规划归档** | 新规划生成（替换旧版） | 旧规划正文 | L2 历史摘要 |
| **指南归档** | 指南进入终态 | 指南正文 + 用户反馈 | L1 事实 + L2 摘要 |
| **任务推理压缩** | reasoning_notes > 10 条 | 最早 N 条 notes | Task.summary 更新 |

### 2.2 对话压缩触发条件

```python
# 生产配置
LAYER3_ARCHIVE_CONFIG = {
    "max_recent_turns": 25,          # 保留最近 N 轮完整对话
    "compression_threshold": 25,     # 超过此轮次触发压缩
    "compression_batch_size": 5,     # 每超出 batch_size 轮集中压缩一次
    "max_summaries": 10,             # 最多保留的对话摘要数
}
```

**触发逻辑**：
- 当用户消息数 > `compression_threshold` 时检查
- 超出部分达到 `compression_batch_size` 的倍数时触发
- 例：阈值 25，批量 5 → 30 轮触发，35 轮再触发

### 2.3 报告/规划归档触发条件

- 当生成**新版本**报告/规划时，自动归档**旧版本**
- 修改操作（version++）不触发归档
- 归档时为旧版本生成 `summary` 和 `one_liner`

### 2.4 指南归档触发条件

| 状态变更 | 是否触发归档 | 说明 |
|:--------|:----------:|:----|
| `in_progress` → `completed` | ✅ | 用户完成任务，提取反馈信息 |
| `in_progress` → `cancelled` | ✅ | 任务取消，记录原因 |
| `in_progress` → `expired` | ✅ | 任务过期，自动触发 |
| `in_progress` → `paused` | ❌ | 暂停可恢复，不归档 |
| `pending` → `in_progress` | ❌ | 状态流转，不归档 |

### 2.5 任务推理压缩触发条件

```python
LAYER3_ARCHIVE_CONFIG = {
    "reasoning_limit": 10,             # 超过此数量触发压缩
    "reasoning_compression_batch": 5,  # 保留最近 5 条，压缩之前的
}
```

## 三、摘要生成规范

### 3.1 对话摘要 (Conversation Summary)

**目标**：保留对话的**互动质量**、**关系动态**、**关键事实/约定**。

| 维度 | 规范 |
|:----|:----|
| **长度** | 100-200 tokens（约 150-300 字） |
| **必含要素** | 互动质量、关系动态变化、关键事实或约定 |
| **禁止** | 流水账式罗列（"用户问好，AI回复好"） |
| **话题标签** | 3-5 个关键词，逗号分隔 |

**正确示例**：
```
"用户尝试约饭被拒绝，Crush 表示最近忙。军师分析可能是回避型依恋，建议降低压力。
用户透露 Crush 说下周三有空。约定下周一再制定邀约计划。"
```

**错误示例**：
```
"用户发来消息，AI 回复。用户又发消息，AI 又回复。中间聊了天气、吃饭、工作。"
```

### 3.2 报告摘要 (Status Report Summary)

**目标**：保留报告的**阶段判定**、**核心问题**、**关键变化**。

| 字段 | 规范 | 示例 |
|:----|:----|:----|
| **summary** | 100-150 字，包含阶段判定、ACR 得分变化、核心问题 | "关系处于 L2 好感期初期，互动频率稳定但缺乏深度话题。ACR 得分：A65/C70/R55。主要问题：用户追问过多导致 Crush 有压力感。建议放慢节奏，等待 Crush 主动。" |
| **one_liner** | ≤30 字，格式 `{阶段}，{核心状态}` | "L2 阶段，推进受阻，缺乏独处机会" |

### 3.3 规划摘要 (Action Plan Summary)

**目标**：保留规划的**阶段目标**、**核心策略**、**执行重点**。

| 字段 | 规范 | 示例 |
|:----|:----|:----|
| **summary** | 100-150 字，包含阶段目标、核心策略、关键里程碑 | "第一阶段目标：建立稳定聊天节奏，每周 3-4 次主动联系。核心策略：降低压力，以轻松话题为主，避免追问。关键里程碑：两周内实现 Crush 主动发起对话。" |
| **one_liner** | ≤30 字，格式 `{目标}，{策略}` | "建立聊天节奏，降压策略" |

### 3.4 指南摘要 (Guide Summary)

**目标**：保留指南的**执行情况**、**用户反馈**、**关键收获**。

| 字段 | 规范 | 示例 |
|:----|:----|:----|
| **summary** | 必须包含三个部分 | 见下方模板 |
| **one_liner** | ≤30 字，核心结果 | "破冰成功，Crush 回复积极" |

**Summary 模板**：
```markdown
**执行摘要**: 用户按照建议发送了破冰消息，Crush 回复积极。
**用户反馈**: "她回复了！说周末有空，感觉有戏"
**关键收获**: Crush 对约会持开放态度，周末可能有空。
```

### 3.5 任务推理摘要 (Reasoning Summary)

**目标**：保留推理过程中的**关键决策**和**排除假设**。

| 维度 | 规范 |
|:----|:----|
| **长度** | 50-100 tokens |
| **必含要素** | 关键决策点、排除的假设、进展阶段 |

**示例**：
```
"分析过程中排除了第三者可能性（无证据支持），判断 Crush 冷淡系工作压力所致。
决定采用降低压力策略。用户反馈 Crush 回复变快，进入试探升温阶段。"
```

## 四、Layer 1 归档规则

### 4.1 信息归属判断

从压缩内容中提取的信息，需要判断属于 3×3 矩阵的哪个格子：

**第一步：判断主体 (Subject)**

| 主体 | 定义 | 关键词示例 |
|:----|:----|:---------|
| `user_info` | 关于用户本人 | "我"、"用户"、性格、职业、习惯 |
| `crush_info` | 关于 Crush | "她/他"、"Crush"、性格、喜好、背景 |
| `both_info` | 关于双方关系 | "我们"、认识方式、互动频率、共同点 |

**第二步：判断来源 (Source)**

| 来源 | 定义 | 可信度 | 示例 |
|:----|:----|:------|:----|
| `fact` | 有直接证据（截图、聊天记录） | 🥇 最高 | "Crush 说周末要加班"（来自截图） |
| `ai_provide` | AI 基于证据的分析推断 | 🥈 中等 | "依恋类型：焦虑型"（基于行为分析） |
| `user_provide` | 用户口述（可能有滤镜） | 🥉 较低 | "她对我有好感"（用户自述） |

### 4.2 长期事实 vs 短期事实判断

这是决定信息写入 Layer 1 还是 Layer 2 的关键判断：

| 类型 | 定义 | 特征 | 示例 | 写入目标 |
|:----|:----|:----|:----|:--------|
| **长期事实** | 长时间有效的信息 | 不会在近期过期 | "Crush 是独生女"、"用户有健身习惯"、"两人是同事关系" | **Layer 1** |
| **短期事实** | 有时效性的信息 | 近期发生、会过期 | "下周三要出差"、"最近在加班"、"今天心情不好" | **Layer 2 动态情报** |

**判断规则**：
```markdown
问自己：这条信息 30 天后还有参考价值吗？
- 是 → 长期事实 → Layer 1
- 否 → 短期事实 → Layer 2 动态情报（设置 TTL）
```

### 4.3 写入规则

#### 4.3.1 user_provide：同属性覆盖

当用户提供的**同一属性**有新值时，直接覆盖旧值：

```
示例：
- 旧：「年龄：26」
- 新：「年龄：28」
- 结果：删除旧的，写入新的
```

**"同一属性"判断**：由 LLM 判断两条信息是否描述同一属性。

#### 4.3.2 fact：全量追加 + 长短期分流

客观事实**不覆盖，全量追加**，但需要先判断长短期：

```
新事实输入
    ↓
LLM 判断：长期 or 短期？
    ├── 长期 → Layer 1 fact 列表追加
    └── 短期 → Layer 2 动态情报板（设置 TTL）
```

#### 4.3.3 ai_provide：同维度覆盖

当 AI 产生新的分析结论时，覆盖**同一分析维度**的旧结论：

```
示例：
- 旧：「依恋类型：焦虑型」
- 新：「依恋类型：安全型」
- 结果：删除旧的，写入新的（同属"依恋类型"维度）
```

### 4.4 不写入 Layer 1 的信息

以下分析维度**不写入 Layer 1**（因为会在 Layer 2 现状报告中常驻，避免重复）：

| 排除的维度 | 原因 |
|:---------|:----|
| 关系阶段（L1-L4/T1-T3） | 在现状报告中常驻 |
| ACR 三维分析 | 在现状报告中常驻 |
| 核心问题/风险点 | 在现状报告中常驻 |
| 当前行动建议 | 属于指南/规划内容 |

**应该写入 Layer 1 的 AI 分析**：

| 写入的维度 | 示例 |
|:---------|:----|
| 依恋类型 | `依恋类型：焦虑型` |
| 性格特征 | `性格：内向、敏感` |
| 沟通风格 | `沟通风格：直接型` |
| 兴趣偏好 | `兴趣：喜欢看综艺、咖啡` |

### 4.5 去重规则

写入前，调用 LLM 判断新信息是否与已有信息**语义重复**：

```markdown
判断以下两条信息是否表达相同的含义：
- 已有信息：「职业：程序员」
- 新信息：「用户是一名软件工程师」

如果语义相同，返回 "duplicate"；否则返回 "new"。
```

- 返回 `duplicate` → 不写入
- 返回 `new` → 执行写入

## 五、Layer 2 动态情报规则

### 5.1 动态情报 TTL 计算

| 类别 | 关键词示例 | 默认有效期 | 说明 |
|:----|:---------|:---------|:----|
| **日程 (schedule)** | "下周三去上海"、"明天加班" | 事件结束 + 2天 | 有明确时间点 |
| **情绪 (mood)** | "最近很烦"、"今天超开心" | 3天 | 情绪易变 |
| **状态 (status)** | "生病了"、"在忙"、"刚分手" | 7天 | 当前状态 |
| **意向 (intent)** | "想看电影"、"在找借口" | 14天 | 潜在需求 |
| **其他** | 无法归类的信息 | 14天 | 默认值 |

**TTL 计算规则**：
- **明确时间点**：如 "1月5日去展会"，`expire_at` = `2024-01-07`（事件后2天）
- **模糊时间点**：如 "下周"，取下周日的次日
- **无时间点**：根据类别赋予默认 TTL

### 5.2 置信度判断标准

| 置信度 | 条件 | 示例 | 是否记录 |
|:------|:----|:----|:--------|
| **高 (0.8-1.0)** | 用户明确、认真表述；有具体时间/地点；非玩笑语境 | "下周三确定去上海" | ✅ 记录 |
| **中 (0.5-0.8)** | 用户转述他人的话；用户的推测或猜想 | "她好像最近忙" | ✅ 记录 |
| **低 (0.3-0.5)** | 调侃语境；用户自己也不确定 | "可能吧，不好说" | ✅ 记录（标注低置信度） |
| **不记录 (<0.3)** | 明显玩笑；与已有信息严重矛盾；用户说"我瞎说的" | "开玩笑的啦" | ❌ 不记录 |

**重要**：必须在 `confidence_reason` 字段中说明判断依据！

### 5.3 动态情报数据结构

```python
DynamicIntelItem = {
    "id": str,                    # 唯一标识 (uuid[:8])
    "content": str,               # 情报内容
    "created_at": str,            # ISO 格式时间
    "expire_at": str,             # ISO 格式过期时间
    "subject": "user" | "crush",  # 归属
    "category": str,              # 类别（schedule/mood/status/intent/other）
    "confidence": float,          # 置信度 (0.0-1.0)
    "confidence_reason": str,     # 置信度判断依据（必填）
    "source_type": "conversation",
}
```

## 六、压缩执行流程

### 6.1 对话压缩流程

```
检测到 Layer 3 超限
        ↓
获取需要压缩的消息（最早的 N 轮）
        ↓
调用 Organize Agent
        ↓
    ├── 生成对话摘要 → 存入 Layer 3 conversation_summaries
    ├── 提取长期事实 → 写入 Layer 1 (fact)
    ├── 提取短期事实 → 写入 Layer 2 (dynamic_intels)
    └── 提取 AI 分析 → 写入 Layer 1 (ai_provide，排除常驻维度)
        ↓
从 messages 中删除已压缩的消息
```

### 6.2 报告归档流程

```
生成新报告
        ↓
将旧报告移入 status_report_history
        ↓
调用 Organize Agent 处理旧报告
        ↓
    ├── 生成 summary（中等摘要）→ 更新旧报告对象
    ├── 生成 one_liner（一句话）→ 更新旧报告对象
    └── 提取关键结论 → 写入 Layer 1 (ai_provide)
        ↓
设置旧报告的 archived_at 时间戳
```

### 6.3 指南归档流程

```
指南进入终态（completed/cancelled/expired）
        ↓
调用 Organize Agent 处理指南
        ↓
    ├── 生成 summary（执行摘要 + 用户反馈 + 关键收获）
    ├── 生成 one_liner（核心结果）
    ├── 从用户反馈中提取事实 → 写入 Layer 1 (fact)
    └── 提取动态态势 → 写入 Layer 2 (dynamic_intels)
        ↓
更新指南对象的 summary/one_liner/completed_at 字段
```

### 6.4 任务推理压缩流程

```
检测到 reasoning_notes > 10 条
        ↓
取出 0 到 (n-5) 条 reasoning
        ↓
调用 LLM 生成摘要
        ↓
将摘要追加/更新到 Task.summary 字段
        ↓
reasoning 列表只保留最近 5 条
```

## 七、并发与一致性

### 7.1 处理状态标记

压缩操作开始前设置 `processing_status`，防止重复触发：

```python
layer3_memory = start_layer_processing(
    layer3_memory,
    processing_type="compression",
    fallback_data={...},  # 降级数据快照
)
```

### 7.2 失败回滚

如果压缩过程失败：
- 不更新任何层级的数据
- 清除 `processing_status`
- 日志记录失败原因
- 下次触发时重试
